# 課題追加

## 発動条件

次のいずれかに該当する場合に使用する。

- ユーザーが新しい課題の「追加」または「新規作成」を明示的に依頼した場合
- 設計メモを確認して未登録と判定できる課題番号を伴い、新しい課題の概要または弾幕定義を入力した場合。この場合は「追加」や「新規作成」という語がなくても使用する

未登録の課題番号を伴わないアイデア、仮案、一般的な課題設計の相談だけでは使用しない。

次の依頼では使用しない。

- 既存課題の修正
- 数値調整
- バグ修正
- リファクタリング
- 課題設計についての相談
- 実装を伴わないレビュー

## 1. 追加前の定義確認

### 初回定義テンプレート

このSkillが発動した最初の入力では、入力が概要だけか詳細付きかにかかわらず、実装や設計メモの変更を行わず、ユーザーのプロンプトから解釈した内容を「初回定義テンプレート」としてコードブロックで返す。

- ユーザーが指定した値と、入力解釈規則または明確な既定値から一意に確定する値は記入する。
- 項目名に`[default:値]`がある場合、回答欄が空欄ならそのdefault値を確定値として採用する。回答欄へ値が入力されている場合は入力値を優先する。
- `default`が別項目の参照である場合は、参照先の確定値を採用する。参照先が未確定ならdefaultを推測せず、参照先を不足項目として扱う。
- `default`の記載がない空欄は未確定として扱い、既存課題の値などから推測して補完しない。
- 未指定、複数解釈可能、または確認が必要な値は空欄にする。推測値や候補をテンプレートへ記入しない。
- ユーザーが示した構成要素、英字系統、段階見出しを維持し、対象となる構成要素・段階ごとに必要項目を繰り返す。
- 概要から構成要素や段階を特定できない場合は、課題共通項目と`構成要素または段階名：`から始まる1ブロックを提示する。
- 初回入力だけで全項目が確定しているように見える場合も、省略せずに解釈済みの全項目を提示する。
- ユーザーがテンプレートへ追加入力するか、内容を明示的に確認するまで、ファイルを変更しない。

初回定義テンプレートは、次の形を基準とする。見出しは入力された構成に合わせて置き換える。

```text
課題区分[Basic／Applied／Advanced／Final／その他]：
課題番号または追加位置[区分-連番／挿入位置]：
課題名[文字列]：
課題全体の周期[s]：

構成要素または段階名[名称]：
構成要素[要素名]：
発射元[Boss／○第N段階の弾]：Boss
発射開始時間[s／周期内時刻]：
発射周期[s][default:課題全体の周期を参照]：
1回あたりの生成数[発]：
発射方向および角度間隔[方向基準・deg]：
編隊形状[default:なし／一字／I字／V字／逆V字／X字／その他]：
編隊内座標[無次元座標／なし]：
編隊間隔拡大率[Unit/s／なし]：sx=；sy=
矩形補正[default:なし／あり]：
矩形補正基準弾[なし／中央の自機狙い弾／偶数way中央の仮想弾／その他]：
矩形補正基準初速[Unit/s／なし]：
矩形補正式[式／なし]：
形状崩れの許容[なし／角速度分布およびその上位概念では許容／その他]：
初速[Unit/s]：
線形加速度[Unit/s²][default:0]：
角速度[deg/s]：
角加速度[deg/s²]：
分裂条件および分裂数[条件・発]：
最大寿命[s][default:30]：
画面外返却[default:あり／なし]：
距離制限[画面中心基準／Unit／なし][default:画面中心から画面四隅までの距離の2倍]：
衝突時返却[default:あり／なし]：
発射元終了時返却[あり／default:なし]：
課題終了時返却[default:あり／なし]：
脅威度[整数]：
予告線[なし／あり][default:なし]：
その他[なし／自由記述]：
```

初回テンプレートへの回答後、実装前に、回答を反映して解釈した弾幕定義を列挙する。

定義形式は、リポジトリ内の次のディレクトリを参照し、既存ファイルの形式に合わせる。

`memo/ルール統一設計メモ`

少なくとも次の情報を整理する。

- 課題区分
- 課題番号または追加位置
- 課題名
- 課題全体の周期
- 構成要素
- 発射元
- 発射開始時間
- 発射周期
- 1回あたりの生成数
- 発射方向および角度間隔
- 編隊形状、編隊内座標およびx・y方向の間隔拡大率
- 矩形補正の有無、基準弾、基準初速、補正式
- 角速度分布およびその上位概念における形状崩れの許容
- 初速
- 加速度
- 角速度
- 角加速度
- 分裂条件および分裂数
- 生存時間またはプール返却条件
- 脅威度
- 予告線の有無
- その他、実装に必要な固有パラメータ

### 入力解釈規則

- 空欄時defaultとして、発射周期と発射継続時間は課題全体の周期、編隊形状と矩形補正はなし、加減速時間は0秒、最大寿命は30秒、画面外返却はありを採用する。
- 現行スクリプトに合わせ、距離制限は画面中心から画面四隅までの距離の2倍、衝突時返却はあり、発射元終了時返却はなし、課題終了時返却はありをdefaultとする。距離制限は固定Unit値ではなく、カメラのviewport座標とaspect比から算出する。
- 課題終了時返却のdefaultは、課題の初期化およびリスタートで`ClearEnemyAttacks()`が全アクティブ弾を返却する現行処理を指す。シーン終了時はUnityが破棄するため、プール返却とは区別する。
- 発射元はBossオブジェクトで固定する。
- 乗算記号および回数表記では、`*` と `×` の表記ゆれを同じ意味として扱う。
- `T` は課題周期の開始を0とする周期内経過時間であり、周期ごとに0へリセットする。発射時刻またはそれ以下の項目に式がある場合は、その発射時刻の `T` を式へ代入する。例えばT+8で発射する弾に `弾速200+T×5` と指定された場合、初速は240Unit/sと解釈する。
- `A第N段階` など同じ英字の段階表記は、第N-1段階の弾を発射元として第N段階を分裂生成する意味と解釈する。
- 分裂対象の限定がなければ、直前段階で生成されたすべての弾を対象とする。親を消す指定がなければ、分裂後も親を残す。
- 段階定義は、後述される分裂数、way数、角度配列、弾構造数と照合し、生成数が一致しない場合は停止して確認する。
- `○秒遅延` は分裂開始までの遅延を示す。遅延指定がなければ0秒とする。
- `○秒周期×○` は発射周期と回数を示す。`×○` がなければ回数無制限とし、`単発`は1回と解釈する。
- 線形加速度が明示されていなければ0Unit/s²とする。
- 脅威度が明示されていなければ、`memo/ルール統一設計メモ/脅威度ルール.txt`を読み、規則から算出する。規則から一意に算出できなければ停止して確認する。
- 予告線が明示されていなければ、予告線なしとする。
- 矩形補正が指定された編隊では、基準弾を中心の自機狙い弾とする。偶数wayで中央弾が存在しない場合は、中央の仮想弾を基準弾とする。
- 一字・I字・V字・逆V字・X字編隊では、基準方向単位ベクトルを`forward`、垂直方向単位ベクトルを`side`、編隊内座標を`(x(k), y(k))`、x・y方向の間隔拡大率を`sx`・`sy`とし、補正後速度ベクトルを`v(k)=(S+sy*y(k))*forward+sx*x(k)*side`とする。
- 角速度分布およびその上位概念では矩形補正を適用せず、編隊形状の崩れを許容する。

プロンプトで定義されていない項目について、既存形式または明確な既定値から一意に決められない場合は、ファイルを変更せずに停止する。

課題全体の周期が指定されていない場合は、他の値から推測せず、ファイルを変更せずに停止する。

停止時は、次をユーザーに提示する。

- 確定している定義
- 曖昧な定義
- 実装結果を変える可能性がある選択肢
- 確認が必要な質問

最後に、ユーザーがそのままコピーして値だけ追記できる「追加入力テンプレート」をコードブロックで提示する。

- テンプレートには不足または選択が必要な項目だけを含め、すでに確定している項目を再掲しない。
- 不足項目が構成要素や段階に属する場合は、対象を特定できる最小限の階層見出しを残す。
- 項目名は既存設計メモまたはユーザー入力の表記に合わせ、値は空欄にする。推測値や推奨値を記入しない。
- 複数の対象に同名の不足項目がある場合は、それぞれの階層の下へ分けて記載する。
- 選択肢の説明はテンプレートの外で行い、テンプレート自体は追加入力として成立する形式にする。

例えばA第2段階の弾速だけが不足している場合は、次の形式で返す。

```text
A第2段階[段階名]：
弾速[Unit/s]：
```

## 2. 課題区分の確認

Basic、Applied、Advanced、Finalなどの追加先区分と、追加位置をプロンプトから特定する。

次のいずれかに該当する場合は、実装せずに停止して確認する。

- 課題区分が指定されていない
- 複数の区分として解釈できる
- 課題番号または挿入位置が一意に定まらない
- 指定された区分と設計メモの構造が矛盾する

課題区分や番号を推測して追加してはならない。

## 3. 構造確認

実装前に、定義値と既存実装を照合する。

次を確認する。

- 弾速、加速度、角速度、角加速度、発射周期、分裂数、継続時間の単位
- 周辺課題と比較して極端に速い、遅い、大きい、小さい値
- 小数点、符号、桁、度とラジアン、秒とフレームの取り違え
- 未指定値が暗黙に既定値へ置き換わっていないか
- 生成数が意図せず乗算される構造になっていないか

誤字または指定ミスの可能性がある値は勝手に修正せず、疑わしい理由と比較対象を提示して確認する。

## 4. ライフサイクル確認

加速度、角加速度、時間変化、分裂のいずれかが定義されている場合、その変化が完了する前にオブジェクトがプールへ返却されないことを確認する。

原則として、次の関係を満たすことを確認する。

`最も早く成立しうるプール返却時刻 >= 最後の変化または分裂が完了する時刻`

次の返却条件を確認対象とする。

- 生存時間切れ
- 画面外または境界外への退出
- 距離制限
- 衝突
- 発射元や管理オブジェクトの終了
- 課題終了時の一括返却
- その他の自動返却条件

条件を満たさない可能性がある場合は、実装前に報告して確認する。

## 5. 負荷見込み

課題実行中に同時存在しうるオブジェクト数の最大見込みを、プールまたはPrefabの種類ごとに計算する。

計算には次を含める。

- 1回の発射数
- 発射周期
- 発射継続時間
- 各オブジェクトの最大生存時間
- 複数発射元
- 全方位複製
- 時間差発射
- 分裂前の親オブジェクト
- 分裂後の子オブジェクト
- 複数構成要素の重複期間
- 予告線、レーザー、エフェクトなど別プールのオブジェクト

各プールについて、次を報告する。

- 初期プール数
- 最大同時存在数の見込み
- 初期プール数との差
- 不足時の追加生成数の見込み
- 計算上の前提
- 厳密値を出せない場合は安全側の上限

初期プール数を超える場合でも、ユーザーの指定なしに値を変更しない。必要数と変更候補を報告する。

## 6. 実装とテスト

定義と追加位置が確定した場合のみ実装する。

実装後は、プロジェクトで利用可能なコンパイルまたはテスト手段を実行し、少なくとも次を確認する。

- コンパイルエラーがない
- 実行したテストでエラーがない
- 新規課題が指定された区分と位置に登録されている
- 必要なPrefab、プール、参照が欠落していない

テストを実行できない場合は、実行したと偽らず、実行できなかった理由と未確認項目を明記する。

## 7. 設計メモへの反映

実装とテスト確認が完了した後、次のディレクトリにある該当ファイルへ新規課題の定義を追記する。

`memo/ルール統一設計メモ`

既存ファイルの記載形式、並び順、単位、用語に合わせる。

実装に失敗した場合や定義が未確定の場合は、確定済みの課題として設計メモへ追記しない。

## 完了報告

次をまとめて報告する。

- 追加した課題と追加位置
- 実装した弾幕定義
- 構造確認で検出した注意点
- 最大同時オブジェクト数の見込み
- 初期プール数との比較
- 実行したテストと結果
- 更新した設計メモ
- 残っている未確認事項
