『2D宇宙戦争』恒星系マップシーン
作成：2026年11月12日｜設計メモ

【位置づけ】
高縮尺の独立シーン。攻略先の選択、航行、敵部隊の移動、接敵判定を扱う。
道中戦闘・主戦闘とは物理座標を連続させず、論理情報を受け渡す。
本メモは仕様の整理であり、シーンを実装済みであることを意味しない。

【参照元】
・座標系とステージデータ構造.md：座標・部隊運動・シーン間の関係の詳細。
・未決定を決定したやつ.txt：攻略先選択、出撃地点、到達判定。
・恒星系マップ試作.md：既存試作の記録。旧重力実験を現行仕様として扱わない。

【座標と航行】
・恒星系全体の位置は倍精度で管理する。
・恒星系マップ1 U＝戦闘シーン1,000,000 Uは尺度の目安。
・マップのAUはゲーム内単位。100 U＝1 AUは未確定。
・毎回、第4惑星の拠点から出撃する。
・B24恒星系マップ内の攻略先は最初から全て選択できる。
・攻略先の未来位置へ直線移動する基準で航路を計算する。
・ステージ選択時に航路を計算し、主戦闘領域到達までは自由移動不可。
・移動中も任意のタイミングで撤退を指示できる。帰還はゲームにしない。
・攻略先への到達判定は半径0.5 AU。敵部隊との接敵距離とは別の指定。
・会合計算ではプレイヤーを等速直線運動として扱う。

【惑星と敵部隊の運動】
惑星・哨戒部隊：恒星に対する楕円軌道。
防衛部隊：惑星に対する円軌道。半径・角速度・開始位相を指定する。
攻撃部隊：指定速度で直線移動し、プレイヤーとの会合点へ向かう。

楕円軌道はEllipticalOrbitDataで指定する。
・semiMajorAxis：double、軌道長半径
・eccentricity：double、離心率（0以上1未満）
・periapsisDeg：double、近日点方向（度）
・periodDays：double、公転周期（日）
・initialMeanAnomalyDeg：double、初期平均近点角（度）

重力の数値積分・軌道補正は行わない。
軌道に沿う部隊は、会合のための変針を行わない。
各道中戦闘部隊はEnemyFormationDataを持つ。

【会合計算】
軌道に沿う部隊との会合は、プレイヤーと敵部隊の将来位置を同じ経過時間で評価する。
攻撃部隊は二次方程式で会合点を求める。

p：プレイヤー座標、v：プレイヤー速度ベクトル
e：攻撃部隊座標、s：攻撃部隊の速さ、t：会合までの時間
r = p - e
(v・v - s²)t² + 2(r・v)t + r・r = 0
会合点 = p + v t

座標・速度・時間の単位を統一する。解の選択や会合不成立時の扱いは未決定。

【戦闘への移行と復帰】
1. 攻略先を指定して航行する。
2. 敵部隊との接敵で道中戦闘へ移行する。
3. 主戦闘領域への到達・防衛部隊との接敵に対応して主戦闘へ移行する。
4. 戦闘中は恒星系マップの航行を停止する。
5. 戦闘終了後は同じ接敵地点から航行を再開する。

戦闘中の経過時間によってマップ上の航行位置を進めない。
接敵位置・参加部隊・艦の状態・戦闘結果などを受け渡す構成。具体的な引継ぎ範囲は未確定。
戦闘内の艦船・砲弾の位置や速度を、マップ座標へ厳密に変換する方式にはしない。

『2D宇宙戦争』恒星系マップシーン 要件・設計メモ
記録日：2026-11-15
対象：B-24恒星系マップシーン
状態：設計メモ。実装・実機検証完了を意味しない。
記述区分：［要件］ ユーザーが指定した内容／［提案］ 会話中に提示した実装案／［未決定］ 今後の判断事項。
1. シーンの目的と対象範囲
［要件］既存の恒星系観察用試作を、ステージ選択・出撃・敵部隊の移動・接敵・二種類の戦闘シーンへの遷移を行う本編マップへ改修する。恒星系マップは手動で構築する。

［要件］次の機能を構築する。
- 既存の背景の点描画を残す。
- 再生・一時停止と、最大「1000」までの時間操作GUIを残す。
- 恒星を原点 (0, 0) に配置する。
- 惑星の公転軌道を楕円として管理する。
- 拠点を除く惑星・ラグランジュポイントをクリックすると右側にステージ詳細を表示し、出撃ボタンを提供する。
- 敵部隊の挙動を管理する。
- 接敵判定を行い、道中戦闘・主戦闘領域の二種類へ遷移する。
- 戦闘後にマップ側の配置・航行状態を復元できるようにする。
［既存試作］`StellarSystemMap.cs` は背景点130個、再生・一時停止、1/10/100/1000 日/秒、恒星原点描画、惑星7個、要塞5個、ズーム・パン等を備える。既存の惑星軌道は円軌道であり、マップの時間進行は GravitySimulation.Advance() に結び付いている。

［ロードマップとの関係］11/14改訂版では、座標系・戦闘空間の基盤は第I段階、マップ統合は第III段階。恒星系マップは倍精度、道中戦闘は 5,000×5,000 U、主戦闘は 60,000×60,000 U の独立空間。シーン間で物理座標を連続変換せず、論理データを受け渡す。恒星系横断砲弾・ミサイルと多体重力積分は現MVPの対象外。
2. オブジェクト／コンポーネント構成
以下はユーザー案を基準とする。
StellarSystem
├─ SystemController
│    共通時刻・再生・一時停止・時間倍率
├─ MapRenderer
│    背景の点・軌道線・マーカー・カメラ
├─ CelestialBodies
│    恒星と惑星7個
│    └─ Planet [0..6]
│         ├─ StageManager（惑星のクリックとステージ情報）
│         └─ LagrangePoints [5]
│              └─ L1..L5（それぞれStageManager）
├─ FleetManager
│    プレイヤー艦隊・哨戒部隊・防衛部隊・攻撃部隊の生成／挙動
│    └─ 生成した部隊に engageCollider を付与
├─ EncounterManager
│    接敵イベントの受付・接敵時刻での停止・戦闘発生
├─ SceneTransitionManager
│    戦闘シーンへの遷移と復帰
└─ Canvas / UI
     時間操作と右側ステージ詳細・出撃ボタン
［要件］各惑星が5個の LagrangePoints を持つ。各惑星・ラグランジュポイントに StageManager を付与する。`StageManager` はクリック判定と、サイドメニューへ進行先ID int planetID / int? lagrangeID を送信するAPIを持つ。拠点はステージ選択のクリック対象から除外する。

［提案］各天体に複数存在するため、`StageManager` は実質的にはステージ地点コンポーネント（例：`StagePoint`）として設計するのが自然。ただし名称変更は未確定。

［提案］惑星・L点の正式位置は倍精度の天体データから計算し、Transformは表示用にする。`MapRenderer` は描画を担当し、戦役状態は持たない。`SystemController` の時刻を主とし、重力実験の GravitySimulation から時間進行を独立させる。
3. ステージ選択・出撃
［要件］非拠点の惑星またはL点をクリックすると、右パネルにステージ詳細と出撃ボタンを表示する。

［提案］ステージ地点は planetID と、省略可能な lagrangeID で識別し、敵勢力・編成・攻略状況・出撃可否などはステージデータに分ける。ステージ未登録の天体をどう表示するかは未決定。

［ロードマップ既定］第4惑星拠点から出撃し、目標天体の未来位置へ直線航行する。目的地の到達半径は 0.5 ゲーム内AU。道中戦闘／主戦闘中はマップの時刻・航行を停止する。

［未決定］ゲーム内AU換算、航行速度、UIの「1000」を現状の日/秒として残すか通常時間の1000倍とするか、航路を出撃時に固定するか再計算するか。
4. 楕円軌道・ラグランジュ点
［要件］惑星軌道を楕円として管理する。恒星は原点に配置する。

［提案］惑星に長半径 a、離心率 e、近点方向 ω、初期平均近点角 M0、質量、天体IDを持たせる。ケプラー方程式 M(t)=M0+nt、`M=E-e sin(E)` を解き、時刻から惑星位置を求める。

［注意］既存の OrbitMath.Lagrange() は円軌道・円制限三体問題を前提としている。楕円軌道下のL点追従は厳密には同じ式で表せない。

［提案・未決定］MVPでは惑星と恒星の瞬間距離を使ってL点を近似配置する方式が候補。方式と精度は未確定。
5. FleetManager と engageCollider
［要件］`FleetManager` は自艦・哨戒・防衛・攻撃部隊を管理し、Instantiateする部隊オブジェクトに engageCollider を付ける。

［要件・改訂］`engageCollider` は Unity の CircleCollider2D を持たず、接敵半径だけを持つ論理コンポーネントとする。プレイヤーに付けた engageCollider だけが、他の全 engageCollider との接敵を予測する。

［要件］接敵の予測計算は、少なくとも プレイヤー出撃時、攻撃部隊出撃時、軌道計算後 に行う。予想接触時刻の到来時に時間スケールを0にして戦闘発生処理へ進む。

［提案］敵部隊は哨戒＝楕円軌道、防衛＝対象付近の円軌道、攻撃＝プレイヤーとの会合点への移動とする。これはマップ上の動作であり、戦闘シーン内の操艦AIとは別。

［提案］航路変更、敵撃破・撤退など、予測を無効化する変更が起きた場合も接敵を再計算する。最も早い接敵予定と目的地到着予定を比較して先のイベントを処理する。
6. 接敵時刻の予測計算
6.1 直線等速運動同士
［検討結果］相対初期位置を r0 = E0 - P0、相対速度を v = Ve - Vp とすると、相対距離の二乗は

D²(t) = |r0 + v t|² = |v|² t² + 2(r0・v)t + |r0|²

となり、時間に関する二次関数になる。`|v| > 0` のとき頂点（最接近時刻）は

t_min = -(r0・v) / |v|²

であり、これを有効な航行時間区間に制限して最接近距離を得られる。接敵半径合計を R = Rp + Re とすると、

|r0 + v t|² = R²

の 最小の有効な非負解 が最初の接敵時刻となる。実数解がなくても頂点から最接近距離を求め、非接敵と判定できる。相対速度ゼロ、初期時点ですでに範囲内、航行終了時刻などは別途扱う。
6.2 楕円・円軌道を動く部隊
［検討結果］楕円 x²/a² + y²/b² = 1 は空間座標の二次式だが、ケプラー運動する物体の位置は時間の一次関数ではない。そのため、プレイヤーとの距離二乗は一般には時間の二次関数にならず、単一の放物線の頂点から厳密な接敵時刻は求められない。

［提案］哨戒・防衛部隊は時刻区間ごとに軌道を直線近似し、相対運動の二次式で接敵候補を調べる。候補付近は細分化・数値探索する。近似誤差により接敵を見逃さないための分割基準・検証が必要。

［提案］計算方式を LinearEncounterPrediction と OrbitalEncounterPrediction に分け、結果として 接敵予定時刻 / 対象部隊ID / 接敵予測位置 を EncounterManager に渡す。
7. EncounterManager と戦闘遷移
［要件］`engageCollider` からの接敵イベントを EncounterManager が受け、接敵時点で時間を止める。`SceneTransitionManager` が道中戦闘へ遷移する。目的地到着時には主戦闘領域へ遷移する。

［提案］最大1000倍速でもイベントを飛び越えないよう、予定時刻を超える更新が来たらそのイベント時刻ちょうどに時刻を確定し、天体・艦隊を同時刻の位置へ更新してから停止する。

［注意］既存コードは Time.unscaledDeltaTime を用いて時間を進めるため、`Time.timeScale = 0` だけでは停止が保証されない。`SystemController` 自身の一時停止フラグと共通時刻制御も停止させる。
8. 戦闘シーン復帰データ
［要件］遷移前にPlayerPrefsで次の値を保存する。
キー	指定型	意味
currentTime	float	接敵時点の時刻
StartTime	float	出撃時刻
progressRatio	float	プレイヤーの航路進行割合
planetID	int	進行先惑星
lagrangeID	int?	進行先L点（指定なしあり）


［注意］`PlayerPrefs` は int? を直接保存できないため、未指定を -1 として保存する案。倍精度で時刻を管理するなら SetFloat は精度を落とすため、文字列化等も候補。ユーザーの指定型を変更する決定はまだしていない。

［注意］以上の5値のみで再現可能なのは、初期条件と時刻から位置を一意に計算できる対象に限る。攻撃部隊の過去の進路変更、撃破・撤退状態、固定した航路の到着点などは追加の永続データが必要な可能性がある。

［提案］復帰時は (1) 時刻復元 → (2) 天体・L点復元 → (3) 艦隊生成と状態復元 → (4) プレイヤー航路復元 → (5) 戦闘結果反映 → (6) 接敵再予測 → (7) 再生操作受付、の順とする。同じ部隊との即時再接敵を避ける仕組みも必要。
