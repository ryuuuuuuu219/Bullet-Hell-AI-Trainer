# Project AYBS — 艦体形状生成仕様メモ

作成：2026-11-18

## 1. 対象と根拠

本書は `新しいフォルダー/sennkannTPS/Assets/Script/module` の現行C#から読み取れる実装仕様を記録する。新たな設計決定やUnityでの動作確認を意味しない。`.bak` と `.meta` は実装の根拠に使用しない。

| ソース | 対象処理 |
|---|---|
| `TilingGenerator.cs` | 初期区画、外周からの増設、鏡映、重複判定、軸上の隙間補完 |
| `TilingEnds.cs` | 上下端の形状判定と追加形成 |
| `TilingTestScene.cs` | 生成の呼び出し、描画、コア・装甲・砲塔の割り当て、設定保存 |
| `BattleshipSection.cs` | 区画ID・役割・HP・隣接関係・Colliderとの接続 |
| `BattleshipInstance.cs` | 目標／実区画数の保持、コアとの連結判定 |

`TilingTest.shader`、試射用の`TilingTurretProjectile.cs`、マップ帰還用の`ShipConstructionReturnUI.cs`は形状決定アルゴリズムではない。防御・射撃・移動全般の仕様は本書の対象外。

## 2. 全体の処理順

1. シード・目標区画数・初期形状・初期角度などから`TilingGenerator`を作る。
2. 原点を中心とする初期区画を1枚置き、Y軸対称か確認する。
3. `Step()`で未共有辺へ区画を増設する。鏡映側も同時に追加する。
4. 増設が成功するたびに、条件に合うY軸上の三角形の隙間を補完する。
5. 目標到達、試行上限、増設に使える辺がない場合に通常増設を止める。非対称の初期形状は増設しない。
6. 有効なら`FormEnds()`で上端、下端の順に追加形成する。
7. 最終形状の区画0をコアにし、残りを装甲・砲塔へ割り当てる。
8. Mesh・Collider・隣接関係を構築し、試験用の`BattleshipInstance`へ渡す。

**形状生成と区画の役割割り当ては別段階。** 兵装数・装甲数・艦種は`TilingGenerator`の引数ではなく、現在の試験シーンでは生成後の役割・兵装割り当てに使う。

## 3. 入力と初期値

以下はコードの初期値。保存済みのPlayerPrefsやUnityのシリアライズ値によって、実際のシーンの値は変わり得る。

| 項目 | コード初期値 | 範囲・扱い |
|---|---:|---|
| シード | 試験シーンは2 | `System.Random(seed)`を使用。入力解析失敗時は3 |
| 目標区画数 | 24 | 1～128に制限。コアを含む総区画数の目安 |
| 通常増設の試行上限 | 160 | 1～2000に制限 |
| 初期形状 | 正方形 | `triangleStart=true`で正三角形 |
| 正方形の初期角度 | 0° | Y軸対称になるのは45°刻み |
| 正三角形の初期角度 | 30° | Y軸対称になるのは30°＋60°刻み |
| 端部形成 | 有効 | `formEnds`で切り替え |
| 端部探索深度 | 6 | シーンUIは1～12、生成器APIは0～12 |
| 端部候補評価上限 | 1200 | シーンUIは1～10000、生成器APIは0～10000。各端を別に探索 |
| 区画の一辺 | 100 U | `sectionWorldSize`。生成器内では一辺1 |
| 艦種 | Cruiser | Frigate／Destroyer／Cruiser／Battleship。輪郭そのものは変えない |

`initialAngle`をAPIで省略すると、正方形0°・三角形30°を使う。NaN・無限大は例外。有限角度は360°で剰余を取り、反時計回りに回転する。UIでは`StartAngle`の列挙値から選び、非対称な組み合わせも選択できるが、その場合は増設を停止して角度変更を促す。

## 4. 初期区画と座標

形状計算はUnityに依存しない`double`のXY座標で行う。対称軸はY軸で、鏡映は`(x,y) → (-x,y)`。上下方向の端はYの最大値・最小値から判定する。

- 正方形：`(-0.5,-0.5), (0.5,-0.5), (0.5,0.5), (-0.5,0.5)`。
- 正三角形：`(-√3/6,-0.5), (√3/3,0), (-√3/6,0.5)`。
- どちらも原点が中心。指定角度で回転して最初の区画とする。
- 初期区画は最後まで配列の先頭に残り、試験シーンでコアになる。
- 三角形の面積は`√3/4`、正方形の面積は1。区画数は面積換算せず、どちらも1枚として数える。

座標比較の許容誤差`Epsilon`は`0.000001`。外周辺の集計では座標を100万倍して丸めた文字列キーを使う。重複判定の許容誤差もこの生成器座標上の値であり、描画後のUを直接使わない。

## 5. 通常増設

根拠：`Step()`、`GetFrontier()`、`Attach()`、`MirrorPair()`、`Fits()`、`Overlaps()`。

### 増設する辺の選択

各区画の辺を向きに依存しないキーで数え、1回だけ現れる辺を未共有辺とする。未共有辺を持つ区画を等確率で選び、その区画の未共有辺を等確率で選ぶ。

したがって、全ての未共有辺から直接一様抽選する方式ではない。また、連結した最外周だけを抽出する処理ではなく、内側の穴に面する未共有辺も候補になり得る。

### 追加形状と鏡映

1回の試行では正三角形／正方形を各1/2で選ぶ。辺の始点をA、終点をB、`d=B−A`、外向き法線を`n=(d.y,−d.x)`として、次を作る。

- 正三角形：`A, (A+B)/2 + n√3/2, B`。
- 正方形：`A, A+n, B+n, B`。

生成した区画をY軸で鏡映し、頂点順を反転して鏡映側の区画を作る。自身と鏡映が同じ頂点集合なら1枚、それ以外は2枚を候補とする。

既存区画との重複、および候補2枚同士の重複を分離軸判定で検査する。辺・頂点だけの接触は許可し、内部の重なりを不許可とする。片側だけが入らない場合も候補全体を棄却し、対称性を維持する。

1試行ごとに`Attempts`を増やす。採用できれば`Accepted`を1増やし、棄却なら`OverlapRejected`を1増やす。これらは区画枚数ではなく試行数。未共有辺がなくなった場合は`Attempts`を上限値にして終了する。

## 6. Y軸上の三角形補完

根拠：`FindAxisGap()`。

通常増設の成功後、`x=0.5`の頂点からY軸上の頂点へ向かう未共有辺と、その鏡映側の辺を探す。その辺に外向きの正三角形を付けたとき、鏡映側の頂点まで閉じ、単独でY軸対称かつ重複しない場合に1枚追加する。

- 条件に合う三角形がなくなるまで繰り返す。
- 追加枚数は`AxisGapFilled`に加算する。
- 補完は通常増設の追加試行として数えない。
- 任意の穴を全て埋める処理ではない。Y軸上の特定形状だけが対象。
- 端部探索中にこの補完処理を自動実行することはない。

## 7. 区画数と終了条件

`Reached = InitialSymmetric && Count >= target`。

`Done = !InitialSymmetric || Reached || Attempts >= maxAttempts`。

目標数は厳密な完成枚数でも最終上限でもない。鏡映の2枚追加や隙間補完を終えた後に次の終了判定へ進むため、通常増設だけでも目標を超え得る。端部形成はその後さらに追加でき、最終枚数へ128枚の上限を再適用する処理はない。

逆に、通常増設が試行上限に達した場合は目標未満で止まり得る。端部形成は目標到達時だけでなく、この場合も実行可能。`Done`は端部の完成を意味しない。UIの`HasFinished`は`generator.Done && !generating`であり、端部探索まで終わったかを含む。

## 8. 上下端の形成

根拠：`DetectEnd()`、`FormEnds()`。

### 完成と見なす5形状

| 値 | 表示名 | 判定の概要 |
|---|---|---|
| `TriangleTip` | 三角形の頂点 | 軸対称の三角形の頂点がY軸上の最先端 |
| `TrianglePairTip` | ひし形の頂点 | Y軸上の辺を共有する鏡映三角形ペアの先端 |
| `SquareTip` | 正方形の頂点 | 軸対称の正方形の頂点がY軸上の最先端 |
| `SquareEdge` | 正方形の辺 | 軸対称の正方形の辺が端を作る |
| `SquarePairEdge` | 正方形2枚の辺 | Y軸上の辺を共有する鏡映正方形ペアが端を作る |

全区画の実際のY最大／最小位置で判定し、その最先端の頂点が該当形状だけに属することを要求する。船体内部に同形状があるだけでは完成扱いにしない。

### 探索方法と上限

- 通常増設終了後、同じ生成器では一度だけ実行する。初期形状が非対称なら上下とも「初期形状が非対称」で停止。
- 上端→下端の順。すでに完成形なら追加しない。
- 実船体を変更しない候補状態で、評価値の小さい枝を優先して探索する。
- 各端の探索開始時の最先端を`extreme`とし、対象の縦方向範囲を`floor=max(extreme−2, 反対端の符号付き座標)`より先に制限する。下端ではYの符号を反転して同様に扱う。
- 横幅は探索開始時の`max(abs(x))+1`以内。完全に左半面にある辺は候補から外し、鏡映で左右を形成する。
- 三角形→正方形の順で候補を試し、既存区画との重複を検査する。同一配置は再探索しない。
- 反対側の端が完成済みなら、それを未形成に戻す候補を除外する。
- 評価値は「最先端付近の頂点から軸への接近度」＋`追加区画数×0.12`。保持する候補状態は最大128。
- 探索深度は追加の手数であり、追加枚数ではない。1手で鏡映2枚が増える場合がある。
- 深度・候補評価数などの制約内で解を発見した場合だけ、その追加列を実船体へ反映する。発見できなければ「未形成（探索打切り）」として、その端の失敗候補は反映しない。

端形状の指定選択や、必ず両端を完成させる保証、最小枚数で完成させる保証はない。端部探索では乱数を使用しない。

## 9. コア・砲塔・装甲の割り当て

根拠：`TilingTestScene.SetupTurrets()`。以下は現行試験シーンの実装。

最終区画数をNとすると、区画0がコアで、残りN−1区画を使う。役割リストを作り、Fisher–Yates方式でシャッフルする。形状の鏡映ペアへ同じ役割を割り当てる処理はなく、**輪郭は左右対称でも、砲塔・装甲の配置は左右対称とは限らない。**

| 設定 | 砲塔数 | 装甲数 |
|---|---|---|
| 兵装手動指定OFF | `floor((N−1)/2)` | `N−1−砲塔数` |
| 兵装手動指定ON | `min(N−1, 指定兵装数の合計)` | `N−1−砲塔数` |

### 兵装

- 手動指定は小口径砲・大口径砲・対艦ミサイル・機関砲の4種類。各指定数は0～128。
- 指定総数が使える区画数を超える場合は上記の順で採用し、余剰を切り捨てる。採用後のリストをシャッフルする。
- グレードは`BuildWeaponChoices()`の艦種別候補から重み付き抽選する。同じ種類・グレードが複数候補にある場合もそのまま抽選対象にする。手動指定した種類の候補がなければグレード1。
- 砲塔・表示マーカーは各区画の頂点平均位置に置く。

### 装甲

- 手動指定ONではBasic→ERA→AEM（コード上は`AntiEM`）の順に、残った装甲枠まで採用する。各指定数は0～128。
- 不足分はBasicで補完し、採用後に別の乱数列で配置をシャッフルする。
- 手動指定OFFでは試験用の一括`armorMode`を使う。
- 装甲の指定数は装甲枠そのものを増やさず、既存枠の種類配分だけを決める。砲塔手動指定が0ならコア以外は全て装甲となる。

### 乱数と再現条件

- 輪郭：`new System.Random(seed)`。
- 役割・兵装：`new System.Random(unchecked(seed*397) ^ (int)shipClass*7919 ^ N)`。
- 手動装甲の配置：`new System.Random(unchecked(seed*733 + N*37 + 1151))`。砲塔側の乱数列を消費しない。

再現にはシードだけでなく、目標数・試行上限・初期形状／角度・端部設定・艦種・割り当て設定・同じコードと実行環境が必要。最終区画数が変わると、割り当て側の乱数シードも変わる。船体の中央や端へ特定兵装を優先配置する処理はない。

## 10. 描画・区画接続・破壊との関係

- 生成器の頂点を`float`へ変換し、`sectionWorldSize`倍してXY平面に描画する。
- 1区画ごとにGameObjectとMeshを作る。三角形は1三角形、正方形は2三角形で描画する。
- 最終表示で区画ごとに`PolygonCollider2D`を作り、同じ頂点列を設定する。`CreateTestSection()`では最後に`isTrigger=false`とし、防護分析用のCastで参照できるようにしている。
- 区画IDは生成配列のインデックス。2区画の一致頂点が2個以上なら相互に隣接登録する。頂点1個だけの接触は隣接扱いにしない。
- `BattleshipInstance`には目標数・実数・シード・区画一覧を渡し、この試験経路では`stationary:true`とする。
- 破壊時は区画0から隣接関係を幅優先探索し、コアから切り離された生存区画も脱落させる。再タイリングや隙間の埋め直しは行わない。
- 再描画時は表示と試験標的を作り直す。生成履歴の再表示を、戦闘中の損傷状態を保存した復元と混同しない。

## 11. 生成履歴と保存

`Frames`には初期区画、成功した増設、軸上の補完、採用した端部追加の各状態を記録する。重複による棄却だけではフレームを追加しない。`Frame.Added`はその表示で新規追加された区画数。

通常の`Generate()`は試行や端部探索の進捗ごとにコルーチンで待機し、表示を更新する。`GenerateForValidation()`は同じ生成・描画経路を同期実行する検証用入口。今回この入口を実行したわけではない。

試験シーンは`ShipBuild.`接頭辞のPlayerPrefsへ、シード、艦種、目標数、試行上限、初期形状、正方形／三角形それぞれの角度、端部形成設定、兵装／装甲手動指定フラグと各指定数を保存する。再生成時やUI変更時、無効化・一時停止・終了時などに保存する。

保存対象は生成・割り当ての入力であり、頂点配列、Mesh、隣接グラフ、損傷状態そのものではない。この保存処理は設備個体のID＋実数文字列による保存仕様とは別。

## 12. 設計メモとの境界・残る確認

| 設計側の方針 | 今回読んだmoduleの実装 |
|---|---|
| 兵装最大7種類と個別数を建造入力にする | 試験UIは固定4種類。形状生成器は兵装入力を受け取らない |
| 装甲区画数0～60、種類別プリセット | 手動配分は種類ごと0～128。装甲総数は生成後の空き枠で決まる |
| コアHP ID0～10、砲塔HP、装甲HPプリセット | この経路では各区画HP100、艦のコアHP上限は全区画の最大HP合計で初期化 |
| 建造終了時に機動性能を算出 | この試験経路は静止標的として初期化。設計式との接続は本書では確認していない |
| 全設備標準搭載、性能を保存 | 形状生成器に設備入力や設備区画生成はない |

現在存在する形状アルゴリズムを「未実装」とは扱わない。一方、設計入力から必要区画数をどう導くか、超過・不足時に再生成するか、7種類の兵装・HPプリセット・設備・ステージデータへどう接続するかは、このコードだけで確定しない。

参照先：「シーン設計1：艦設計システム.txt」「仕様：座標系とステージデータ構造.md」「仕様：未決定事項.txt」。本書の数値は現行コードの観察結果であり、それを理由に既存の確定設計を上書きしない。

確認範囲：ソースの静的読解。Unity Play Mode、実シーンのInspector値、表示・操作・大量シード生成の実行検証は今回行っていない。
