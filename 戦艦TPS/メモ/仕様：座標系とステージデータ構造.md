# 『2D宇宙戦争』座標系・ステージデータ構造案

設計整理：2026年11月11日｜更新：2026年11月12日｜実装前仕様

出典：[予定表作成](chatgpt-conversation://6af3a3cb-3918-83ee-9056-214a4224174f)。ユーザーが提示した整理本文と11月12日の追記を統合した。

ステージデータは、戦闘領域の設定・惑星配置・プレイヤー初期配置・敵艦編成を保持し、敵艦は既存の艦体自動生成システムに渡すパラメータを持つ構成とする。以下は設計案であり、実装済みを意味しない。

## 1. 座標系

### シーン分離の方針（11月12日更新）

| 項目 | 方針 |
|---|---|
| 恒星系マップ | 高縮尺の独立シーン。航行・部隊移動・接敵判定を扱う |
| 道中戦闘 | マップから独立した等倍座標系。遭遇した敵部隊と戦闘する |
| 主戦闘 | 道中戦闘と同じ等倍座標系。拠点や旗艦と戦闘する |
| シーン間の関係 | 物理座標を連続させず、論理的にも分離する |
| 恒星系マップの重力演算・軌道補正 | 廃止。本編システムから除外する |
| 恒星系を横断する長距離攻撃 | 廃止。巡航中の検知・惑星間攻撃への迎撃も廃止する |
| 道中戦闘の発生 | 敵部隊との接敵に統一する |
| 戦闘領域への移行 | 恒星系マップ上の接敵・到着に対応する |

惑星の公転位置を時刻から算出して表示する方式は、重力演算の廃止後も維持できる。

道中戦闘と主戦闘では、物理計算・艦船操作・砲撃・区画損傷などのシステムを共有できる。両者を別シーンにするか、共通戦闘シーンを異なる設定で起動するかは未決定。

この変更は設計方針であり、既存の実装を削除・変更済みであることを意味しない。

### 基本単位

| 項目 | 設定 |
|---|---|
| U | Unityの座標単位 |
| 戦闘空間 | 現実の距離には対応させない |
| 主戦闘領域 | 60,000 U × 60,000 U |
| 道中戦闘領域 | 5,000 U × 5,000 U |
| 最大速力 | 1,000 U/s |
| MVPプレイヤー速力 | 250 U/s |
| MVP仮想敵速力 | 200 U/s |
| 惑星半径の基準値 | 100,000 U |
| 恒星系マップ1 U | 戦闘シーン1,000,000 U |

恒星系マップと戦闘シーンの縮尺関係は尺度の目安として記録する。シーン間で艦船・砲弾の位置や速度をこの比率で厳密に変換する構成にはしない。

地球の直径12,800,000 mを、ゲーム内の惑星直径200,000 Uに対応させると、参考値として `1 U = 64 m`。ただし物理的な縮尺として固定するわけではない。

`恒星系マップ100 U = ゲーム内1 AU` は候補であり、まだ確定していない。

### 主戦闘領域

戦闘領域の中心を `(0, 0)` とし、各軸の範囲を次のように設定する。

```text
-30000 ≦ x, y ≦ 30000
```

惑星はステージごとに半径・位相・距離係数を指定し、主戦闘領域の周囲に配置する。

```text
D = R + 30000k    （1 ≦ k ≦ √2）
P_planet = (D cos θ, D sin θ)
```

| 変数 | 内容 |
|---|---|
| R | 惑星半径（U） |
| k | 距離係数（1〜√2） |
| θ | 惑星配置位相（度） |
| D | 戦闘領域中心から惑星中心までの距離 |

惑星は円形の侵入禁止領域を形成する。艦船・砲弾に重力を作用させる当初案は、恒星系マップの重力演算廃止とは別に扱う。等倍戦闘領域内での重力・弾道計算、および惑星重力を利用する砲撃コンセプトを残すかどうかは未決定。

道中戦闘では5,000 U四方を使用し、惑星配置との関係は今後の設計事項とする。

### 初期配置と領域境界

- 敵艦の初期座標が惑星の侵入禁止領域と重なる場合は、エラーとして検出する。
- 戦闘領域からの離脱は、座標のクランプのみで処理する。主戦闘領域では各軸を `[-30000, 30000]` に制限する。
- 境界処理による速度補正・反射・減衰は行わない。

## 2. ステージデータの階層

```text
StageData                         ステージ識別・設定の親データ
├─ PlanetStageSettings            惑星半径・位相・距離係数
├─ PlayerSpawnData                プレイヤー初期座標・向き
└─ EnemyFormationData             敵艦の構成・配置データ
   └─ EnemyShipData[]             敵艦1隻ごとの建造パラメータ・装備性能・旗艦判定・座標
```

`EnemyFormationData` は複数の `EnemyShipData` を保持する編成データとして整理する。

道中戦闘の敵部隊も `EnemyFormationData` を保持する。戦闘開始時の敵艦の相対座標は編成データに固定し、恒星系マップ上の接近方向に合わせた編成の回転は行わない。

### PlayerSpawnData：プレイヤー初期配置

| フィールド | 型 | 内容 |
|---|---|---|
| position | Vector2 | 戦闘領域内の初期座標 |
| rotationDeg | float | 初期の向き（度） |

初速はデータに持たせない。StageDataに `playerSpawn` として保持する整理案とする。

道中戦闘ではプレイヤーの開始時の向きを右向きに固定する。マップ上の進行方向から開始時の向きを決めない。

## 3. EnemyShipData：敵艦1隻の定義

| フィールド | 型 | 内容 |
|---|---|---|
| weaponIDs | int[7] | 兵装ID配列 |
| weaponCounts | int[7] | 各兵装の数 |
| turretHP | int | 砲塔区画HP |
| armorSettings_Basic | ArmorSetting | Basicの装甲設定 |
| armorSettings_ERA | ArmorSetting | ERAの装甲設定 |
| armorSettings_AEM | ArmorSetting | AEM（対電磁処理装甲）の装甲設定 |
| coreHPSettingID | int | コアHP設定ID |
| seed | int | 艦体生成シード |
| equipmentPerformance | float[14] | 設備性能 |
| isFlagship | bool | 旗艦フラグ。編成内に複数の旗艦を設定できる |
| position | Vector2 | 戦闘領域内の初期座標 |

### 装甲設定の構造

`ArmorSetting` の1要素は次の3項目。

| フィールド | 型 | 内容 |
|---|---|---|
| armorCount | int | 装甲区画の数 |
| hpSettingID | int | HPプリセットID |
| defenseThicknessSettingID | int | 迎撃力・装甲厚の組の設定ID |

現時点の装甲プリセットは以下のとおり。

| 設定ID（仮） | HP | 迎撃力 | 装甲厚 |
|---|---|---|---|
| 0 | 10 | 0.1 | 25 |
| 1 | 50 | 0.12 | 50 |
| 2 | 100 | 0.15 | 100 |
| 3 | 150 | 0.2 | 200 |
| 4 | 200 | 0.25 | 300 |

HP設定IDと迎撃力・装甲厚設定IDは独立して選択する。表のIDは配列インデックスとして使う場合の仮割当。

装甲設定はBasic・ERA・AEM（対電磁処理装甲）の個別フィールドで保持する。各フィールドは共通の `ArmorSetting` 型を使用し、フィールド名で装甲種類を識別する。

### コアHPプリセット

プリセット値は次の11種類とする。

```text
500 / 1000 / 2000 / 5000 / 10000 / 15000 /
20000 / 25000 / 30000 / 40000 / 50000
```

`coreHPSettingID` で参照する。具体的なID割当は未指定。

## 4. Unity C#データ構造案

実装の土台となるデータ定義案。

```csharp
using System;
using UnityEngine;

[Serializable]
public class PlanetStageSettings
{
    public float radiusU = 100000f;
    public float phaseDeg;
    public float distanceFactor = 1f;
}

[Serializable]
public struct PlayerSpawnData
{
    // 初速はデータに持たせない
    public Vector2 position;
    // 道中戦闘の開始時は右向きに固定
    public float rotationDeg;
}

[Serializable]
public class ArmorSetting
{
    public int armorCount;
    public int hpSettingID;
    public int defenseThicknessSettingID;
}

[Serializable]
public class EnemyShipData
{
    // 兵装（それぞれ長さ7）
    public int[] weaponIDs = new int[7];
    public int[] weaponCounts = new int[7];

    // 艦体設計
    public int turretHP;
    // 装甲種類ごとの個別設定
    public ArmorSetting armorSettings_Basic;
    public ArmorSetting armorSettings_ERA;
    public ArmorSetting armorSettings_AEM;
    public int coreHPSettingID;
    public int seed;

    // 設備（長さ14）
    public float[] equipmentPerformance = new float[14];

    // 配置・役割
    public bool isFlagship;
    public Vector2 position;
}

[Serializable]
public class EnemyFormationData
{
    public EnemyShipData[] ships;
}

[CreateAssetMenu(
    fileName = "StageData",
    menuName = "Warship/Stage Data"
)]
public class StageData : ScriptableObject
{
    public string stageID;
    public PlanetStageSettings planet;
    public PlayerSpawnData playerSpawn;
    public EnemyFormationData enemyFormation;
}
```

C#の `int[]` や `float[]` は宣言だけでは長さが固定されないため、兵装7要素・設備14要素という制約は、後で `OnValidate` などによって保証する必要がある。

Unityの `Vector2` は単精度なので、戦闘領域内のローカル座標に使用し、恒星系全体の位置は従来どおり倍精度で管理する構成とする。

## 5. 恒星系マップの敵部隊と戦闘進行

| 部隊 | 恒星系マップ上の行動 | 接敵 |
|---|---|---|
| 哨戒部隊 | 惑星と同様に、恒星に対する楕円軌道で巡回・遊弋する | 航路上で遭遇 |
| 攻撃部隊 | 外縁部へ向かうプレイヤーに差し向けられる。指定速度で直線移動する | 二次方程式で会合点を求めて迎撃 |
| 防衛部隊 | 惑星に対する円軌道をとる。半径・角速度・開始位相を指定する | 主戦闘領域付近で遭遇 |

敵拠点から惑星間ミサイルや誘導砲弾が飛来する仕組みを廃止し、敵部隊の移動・配置が航路選択や道中戦闘の頻度に影響する構成とする。

### 会合点の計算（確定方針）

恒星系マップ上の会合点は、プレイヤーと敵部隊の座標・速度から計算する。

| 対象 | 計算に用いる運動 |
|---|---|
| プレイヤー | 現在の座標・速度を起点とする等速直線運動 |
| 軌道に沿う敵部隊 | 設定された軌道に沿う運動。重力演算は行わず、会合のための変針もしない |
| 攻撃部隊 | 指定速度で直線移動。等速直線運動するプレイヤーとの会合点を二次方程式で求める |

両者の将来位置を同じ経過時間で評価して会合を求める。攻撃部隊は会合点への直線移動とし、軌道に沿う部隊とは計算方法を分ける。

### 楕円軌道データ（確定）

哨戒部隊は惑星と同様に恒星に対する楕円軌道をとる。軌道データは次の定義とし、重力の数値積分は行わない。

```csharp
[System.Serializable]
public class EllipticalOrbitData
{
    public double semiMajorAxis;  // 軌道長半径
    public double eccentricity;   // 離心率 0以上1未満
    public double periapsisDeg;   // 近日点方向
    public double periodDays;     // 公転周期（日）
    public double initialMeanAnomalyDeg; // 初期位相
}
```

`initialMeanAnomalyDeg` は初期の平均近点角（度）を表す。初期位相の基準時刻と軌道長半径の単位は、マップ側の時間・距離の定義と合わせる必要がある。

### 防衛部隊の惑星に対する円軌道（確定）

防衛部隊は惑星を中心とする円軌道をとり、半径・角速度・開始位相を指定する。円軌道の中心は、その惑星の位置に追従する。角速度の単位とデータのフィールド名・型は未指定。

### 攻撃部隊の直線迎撃（確定）

攻撃部隊は移動速度を指定し、等速直線運動するプレイヤーとの会合を二次方程式で計算する。

以下はこの方式を式に整理したもの。`p` はプレイヤー座標、`v` はプレイヤー速度ベクトル、`e` は攻撃部隊座標、`s` は攻撃部隊の速さ、`t` は計算時点から会合までの時間とする。座標・速度・時間の単位は統一する。

```text
r = p - e
|r + v t|² = s² t²
(v・v - s²)t² + 2(r・v)t + r・r = 0
会合点 = p + v t
```

正の会合時刻が得られた場合、その会合点に向けて直線移動する。二次の係数が0になる場合の一次方程式としての処理、複数の正の解の選択、会合不成立時の扱い、会合計算を再実行する条件は未指定。

### 想定する進行

1. 恒星系マップで攻略先を指定する。
2. 航行中に敵部隊と接敵する。
3. 等倍の道中戦闘へ移行する。
4. 戦闘終了後、結果を反映して恒星系マップに復帰する。
5. 主戦闘領域に到達し、防衛部隊と接敵する。
6. 主戦闘を行い、攻略結果を反映する。

## 6. シーン間の情報受け渡し

恒星系マップから戦闘領域へ、艦船や砲弾の軌道を厳密に変換する必要はない。戦闘領域では位置・速度を独立して管理する。戦闘座標の単位は引き続きUとし、現実のメートルには固定しない。

受け渡す論理情報の候補は以下。具体的に何を引き継ぐかは未確定。

- 接敵位置
- 参加部隊
- 艦の状態
- 戦闘結果

例えば、第5惑星付近で敵哨戒部隊が接敵範囲に入ったら、その部隊の情報を渡して道中戦闘を開始し、終了後にプレイヤーと敵部隊の状態を恒星系マップへ反映する。

道中戦闘の相対配置は敵部隊の編成データに固定し、編成を回転させない。プレイヤーの開始時の向きは右向きに固定する。マップ上の会合点の計算と、戦闘領域内の固定配置は別に扱う。

戦闘領域内で編成の相対座標の基準点をどこに置くか、および主戦闘での接近方向の反映は未指定。

### 戦闘中の恒星系マップ航行（確定）

戦闘中は恒星系マップの航行を停止し、戦闘終了後に同じ接敵地点から再開する。戦闘中の経過時間によってマップ上の航行位置を進める処理は行わない。

## 7. 未決定事項

- コアHPプリセットの具体的なID割当
- 設備性能 `float[14]` の数値解釈
- 恒星系マップ100 U＝ゲーム内1 AUという候補の採否
- 道中戦闘と惑星配置の関係
- 等倍戦闘領域内の重力・弾道計算と、惑星重力を利用する砲撃の扱い
- 道中戦闘・主戦闘を別シーンにするか、共通戦闘シーンの設定切替にするか
- シーン間で引き継ぐ情報の範囲
- 戦闘領域内の編成相対座標の基準点と、主戦闘の初期配置への接近方向の反映
- 軌道長半径の単位・初期位相の基準時刻、円軌道の角速度単位とデータ定義

敵編成データを艦体生成システムへの入力として共通化すると、将来のプレイヤー艦建造や敵編成の追加でも、同じ生成処理を再利用できる。
