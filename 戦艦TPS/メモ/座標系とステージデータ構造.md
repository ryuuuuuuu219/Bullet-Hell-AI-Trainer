# 『2D宇宙戦争』座標系・ステージデータ構造案

設計整理：2026年11月11日｜実装前仕様

出典：[予定表作成](chatgpt-conversation://6af3a3cb-3918-83ee-9056-214a4224174f)。ユーザーが提示した整理本文を反映し、表の崩れを整形した。

ステージデータは、戦闘領域の設定・惑星配置・敵艦編成を保持し、敵艦は既存の艦体自動生成システムに渡すパラメータを持つ構成とする。以下は設計案であり、実装済みを意味しない。

## 1. 座標系

### 基本単位

| 項目 | 設定 |
|---|---|
| U | Unityの座標単位 |
| 戦闘空間 | 現実の距離には対応させない |
| 主戦闘領域 | 60,000 U × 60,000 U |
| 道中戦闘領域 | 5,000 U × 5,000 U |
| 最大速力 | 1,000 U/s |
| MVPプレイヤー速力 | 250 U/s |
| MVP仮想敵速力 | 200 U/s |
| 惑星半径の基準値 | 100,000 U |
| 恒星系マップ1 U | 戦闘シーン1,000,000 U |

地球の直径12,800,000 mを、ゲーム内の惑星直径200,000 Uに対応させると、参考値として `1 U = 64 m`。ただし物理的な縮尺として固定するわけではない。

`恒星系マップ100 U = ゲーム内1 AU` は候補であり、まだ確定していない。

### 主戦闘領域

戦闘領域の中心を `(0, 0)` とし、各軸の範囲を次のように設定する。

```text
-30000 ≦ x, y ≦ 30000
```

惑星はステージごとに半径・位相・距離係数を指定し、主戦闘領域の周囲に配置する。

```text
D = R + 30000k    （1 ≦ k ≦ √2）
P_planet = (D cos θ, D sin θ)
```

| 変数 | 内容 |
|---|---|
| R | 惑星半径（U） |
| k | 距離係数（1〜√2） |
| θ | 惑星配置位相（度） |
| D | 戦闘領域中心から惑星中心までの距離 |

惑星は円形の侵入禁止領域を形成し、艦船・砲弾に対して重力を作用させる想定。

道中戦闘では5,000 U四方を使用し、惑星配置との関係は今後の設計事項とする。

## 2. ステージデータの階層

```text
StageData                         ステージ識別・設定の親データ
├─ PlanetStageSettings            惑星半径・位相・距離係数
└─ EnemyFormationData             敵艦の構成・配置データ
   └─ EnemyShipData[]             敵艦1隻ごとの建造パラメータ・装備性能・旗艦判定・座標
```

`EnemyFormationData` は複数の `EnemyShipData` を保持する編成データとして整理する。

## 3. EnemyShipData：敵艦1隻の定義

| フィールド | 型 | 内容 |
|---|---|---|
| weaponIDs | int[7] | 兵装ID配列 |
| weaponCounts | int[7] | 各兵装の数 |
| turretHP | int | 砲塔区画HP |
| armorSettings | ArmorSetting[] | 装甲の種類ごとの設定 |
| coreHPSettingID | int | コアHP設定ID |
| seed | int | 艦体生成シード |
| equipmentPerformance | float[14] | 設備性能 |
| isFlagship | bool | 旗艦フラグ |
| position | Vector2 | 戦闘領域内の初期座標 |

### 装甲設定の構造

`ArmorSetting` の1要素は次の3項目。

| フィールド | 型 | 内容 |
|---|---|---|
| armorCount | int | 装甲区画の数 |
| hpSettingID | int | HPプリセットID |
| defenseThicknessSettingID | int | 迎撃力・装甲厚の組の設定ID |

現時点の装甲プリセットは以下のとおり。

| 設定ID（仮） | HP | 迎撃力 | 装甲厚 |
|---|---|---|---|
| 0 | 10 | 0.1 | 25 |
| 1 | 50 | 0.12 | 50 |
| 2 | 100 | 0.15 | 100 |
| 3 | 150 | 0.2 | 200 |
| 4 | 200 | 0.25 | 300 |

HP設定IDと迎撃力・装甲厚設定IDは独立して選択する。表のIDは配列インデックスとして使う場合の仮割当。

装甲の種類（Basic・ERA・対電磁処理装甲）をどのように識別するかは、配列の並び順で固定する方式か、種類IDを追加する方式かを今後決める。

### 設備性能配列

ユーザー指定の14設備を、次の順序で `float[14]` に対応させる。

| Index | 設備 | 効果 |
|---|---|---|
| 0 | 消火器 | ダメージ軽減 |
| 1 | 予備装甲 | 修復性能 |
| 2 | 発砲遅延装置 | 散布界 |
| 3 | 装填装置 | 装填速度 |
| 4 | カタパルト | 艦載機性能上限・発艦間隔 |
| 5 | 艦載機 | 詳細未定 |
| 6 | レーダー | 索敵範囲 |
| 7 | 空間レーダー | 詳細未定 |
| 8 | MAWS | ミサイル検知 |
| 9 | CIWS | ミサイル迎撃性能 |
| 10 | 電磁バリア | 非実弾兵器の屈折・軽減 |
| 11 | バウスラスター | 旋回性能 |
| 12 | スラスター | 速度性能 |
| 13 | ジェネレーター | 速度・旋回性能補正 |

設備性能の `float` が絶対値、倍率、性能レベルのどれを表すかは未決定。

## 4. Unity C#データ構造案

実装の土台となるデータ定義案。

```csharp
using System;
using UnityEngine;

[Serializable]
public class PlanetStageSettings
{
    public float radiusU = 100000f;
    public float phaseDeg;
    public float distanceFactor = 1f;
}

[Serializable]
public class ArmorSetting
{
    public int armorCount;
    public int hpSettingID;
    public int defenseThicknessSettingID;
}

[Serializable]
public class EnemyShipData
{
    // 兵装（それぞれ長さ7）
    public int[] weaponIDs = new int[7];
    public int[] weaponCounts = new int[7];

    // 艦体設計
    public int turretHP;
    public ArmorSetting[] armorSettings;
    public int coreHPSettingID;
    public int seed;

    // 設備（長さ14）
    public float[] equipmentPerformance = new float[14];

    // 配置・役割
    public bool isFlagship;
    public Vector2 position;
}

[Serializable]
public class EnemyFormationData
{
    public EnemyShipData[] ships;
}

[CreateAssetMenu(
    fileName = "StageData",
    menuName = "Warship/Stage Data"
)]
public class StageData : ScriptableObject
{
    public string stageID;
    public PlanetStageSettings planet;
    public EnemyFormationData enemyFormation;
}
```

C#の `int[]` や `float[]` は宣言だけでは長さが固定されないため、7要素・14要素という制約は、後で `OnValidate` などによって保証する必要がある。

Unityの `Vector2` は単精度なので、戦闘領域内のローカル座標に使用し、恒星系全体の位置は従来どおり倍精度で管理する構成とする。

## 5. 残る設計事項

- `ArmorSetting[]` と装甲種類の対応規則
- コアHPの設定IDに対応するプリセット値
- 設備性能 `float[14]` の数値解釈
- 旗艦を複数設定できるか、1隻に制限するか
- 敵艦初期座標が惑星の侵入禁止領域と重なった場合の処理
- 戦闘領域から離脱した場合の扱い
- マップ座標から戦闘シーン座標への変換と、戦闘中心の決定方法

敵編成データを艦体生成システムへの入力として共通化すると、将来のプレイヤー艦建造や敵編成の追加でも、同じ生成処理を再利用できる。
