## 3. 艦隊ごとの編成・戦闘内配置

### 編成入力と既存定義の関係（11月20日追記）

参照会話：[仕様確認と実装可否](chatgpt-conversation://6b002e80-c544-83ee-8c15-9149b2ed1f80)。最終選択「２で」と対応する回答本文を確認して反映。設計の確定であり、コードへの実装完了を意味しない。

- 艦種プリセットは `ShipType[] shipTypes` で1要素につき1隻を指定する。同じ艦種を複数隻置く場合は同じenum値を繰り返す。`string shipId` と `int number` による編成指定は廃止する。
- 「座標や旗艦フラグを省略」は、入力時の列挙を省略する意味であり、各艦の座標・旗艦フラグなどの定義を削除する意味ではない。以下の個別艦設定の項目は維持する。
- `EnemyFormationData` はScriptableObjectとし、`string formationId`、`ShipType[] shipTypes`、`EnemyShipData[] ships` を保持する。`shipTypes[i]` と `ships[i]` を同じインデックスで対応付ける。
- `shipTypes.Length == ships.Length` を必須とし、不一致はデータ不正としてエラーにする。隻数指定からの展開処理は不要。
- `ShipType` は艦種プリセットの識別用enum。`ShipPresetData` は艦種ごとの建造パラメータを保持するScriptableObject。正式なenum一覧・数値ID・プリセット対応表は別途定義する。会話中のDestroyer_A等と数値IDは例示であり、B24の正式な登録値ではない。
- 座標・向き・旗艦・主AI・代替AIなどの個別設定は `EnemyShipData` に維持する。勝敗・撤退・再接敵・損傷引継ぎの規則は変更しない。
- 撤退艦の保存には元の編成IDと個体識別情報を保持する。配列のインデックスは編成内の位置であり、永続的な個体識別の具体方式は別途定義する。
- この入力方針によって、既存表の空欄が自動的に確定値で埋まるわけではない。未指定の個別値は引き続き未決定とする。

艦1隻につき1行を記入し、行順をshipTypesと同じインデックスで対応させる。建造データはshipTypesから対応するShipPresetDataを参照する。相対座標の基準と、ステージデータの初期座標への変換方法が未確定の間は、両者を同じ値とみなさない。

| 艦の識別名 | 建造データの参照 | 相対X（U） | 相対Y（U） | 初期の向き（度） | 旗艦か | 主AI | 代替AI | AI個別設定の参照 |
|---|---|---|---|---|---|---|---|---|
| | | | | | | | | |

- 旗艦は複数指定できる。
- 敵艦の初速は0 U/s。生成後に操艦AIを開始する。
- 道中戦闘の編成はマップ上の接近方向で回転させない。敵艦の初期の向きは別途記入する。
- 道中戦闘のプレイヤーは右向き、初速0。プレイヤーの配置はステージ側で指定する。
- 通常の初期配置での重複・入力不備はエラーとする。撤退艦の合流時に限る座標補正と混同しない。

### 3.3 艦種プリセットの建造データ（ShipPresetData）

コルベット・高速砲艇・ミサイル艇・レールガン狙撃砲艇・重砲艇・重コルベットの15種は[汎用敵艦プリセット](定義：汎用敵艦プリセット.md)を参照する。ShipType識別名と初期建造値を記載し、数値ID・保存形式との接続は別途定義する。

### 3.4 対象配列・操艦AIの設定

| 項目 | 設定値 | 扱い |
|---|---|---|
| ステージの攻撃対象 | | 戦闘中はGameObject配列 |
| ステージの護衛対象 | | 戦闘中はGameObject配列。敵艦も指定可能 |
| 各艦の操艦AIアンカー | | 各AIの既存条件に従う |
| 固定周回中心・半径など | | 該当する艦のAI個別設定として記入 |

ステージの対象配列と操艦AIのアンカーは自動的に同一とはしない。観測・支援射撃型などの味方艦を対象とする既存条件は維持する。保存した艦の識別情報から生成後のGameObject配列へ解決する方法は未決定。
