- 緑はコア、赤は装甲、黄は小口径砲、橙は大口径主砲、紫は対艦ミサイル、水色は機銃。区画中央の白い円が砲口位置。
- 各砲塔は誕生時から装填を開始し、装填完了ごとにマウスの現在位置へ自動射撃する。散布角は全角で、毎射撃時にその範囲内を一様抽選する。

- 現段階は射撃表示テスト。弾と区画・敵との衝突、ダメージ、対艦ミサイルの発射後誘導、戦艦型動物本体への統合は含まない。弾に区画衝突がないため、自艦区画は表示上そのまま貫通する。

## 操作・生成

- シード・目安区画数・試行上限を設定して「再生成」。初期図形は正方形／三角形のチェックで選ぶ。
- Inspectorの `Square Start Angle`／`Triangle Start Angle` のenumで角度を選ぶ。底辺が左で0°、反時計回りが正。
- 原点の1区画がY軸対称でない角度では初期形状のみ表示する。
- 空き辺のある区画から抽選し、その区画の空き辺と追加形状を抽選する。辺長1、正方形／三角形は各50%。
- Y軸鏡映の組で追加し、内部の重なりがなければ即座に確定する。鏡映で一致する場合は1区画だけ追加。
- 目安区画数または試行上限で終了。最後の対称ペアと局所補完によって目安を超える場合がある。
- 「前」「次」「最終」とスライダーで確定した増設履歴を確認する。
- 青は正方形、橙は三角形、明色はそのステップの追加区画。

凸包計算・凸形状判定・一般的な凹み補完・巻き戻し・Growth Batch Sizeを削除した。

通常成長は分岐探索を使わない。通常の重なり判定は維持する。

## 艦首・艦尾の形成

通常成長の終了後、上端・下端の順に形成する。Inspectorの「艦首・艦尾を形成」で切替可能。
完成条件は、全区画の最上端／最下端が次のいずれかになること。

- Y軸上に重心がある三角形の頂点。
- Y軸上の辺を共有する三角形2枚のひし形の頂点。
- Y軸上に重心がある正方形の頂点。
- Y軸上に重心がある正方形の水平辺。
- Y軸上の辺を共有する正方形2枚の水平辺。

同じ高さに別の張り出しがある場合は未完成とする。
空き辺へ三角形／正方形と鏡映側を追加する候補を分岐探索する。
既定値は片端6手・候補1200件、保持候補128状態。1手は対称ペアまたは軸上の1区画。
探索開始時の端から内側2以内、左右幅は元の最大絶対X+1以内を対象にする。
これらは現行の探索制限で、全形状の端部形成を保証するものではない。
完成済みの反対側の端部を維持し、解が見つかった側のみ履歴へ追加する。
見つからない側は変更せず「未形成（探索打切り）」と表示する。端部追加も目安区画数を超え得る。
通常成長時の局所補完は維持するが、端部探索では各候補の重なり・対称性と完成条件を直接判定する。

## Y軸上の局所補完

増設の確定後、共有されていない辺（区画の境界）を調べる。
X≈0.5の端点とX≈0の端点を結ぶ辺、およびそのY軸鏡映の辺がある場合に、
その2辺に挟まれた辺長1の正三角形を追加する。許容誤差は1e-6。
辺の外側へ作る三角形の第三頂点が鏡映端点と一致し、既存区画と内部が重ならないことを確認する。
両方の辺は同じY軸上の頂点へつながっている必要がある。単にX座標だけが合う頂点は使わない。
追加済みの三角形、共有辺、片側だけの辺、軸から離れた欠落は対象外。
該当箇所がなくなるまで繰り返す。1回の補完は境界辺を少なくとも1本減らすため終了する。
履歴に「Y軸上の三角形を補完」、ステータスに「軸上補完○区画」を表示する。

# タイリングテストシーン

## 操作

- シード・目安区画数（1～128）・試行上限（1～2000）を入力して「再生成」。
- 初期図形は正方形／三角形のチェックで選ぶ。Inspectorの `Square Start Angle` と `Triangle Start Angle` のenumプルダウンで、それぞれの初期角度を指定する（初期値0°／30°）。選択肢は−30°と、0～330°の30°刻みに45°・135°・225°・315°を加えたもの。
- 底辺が左を向く状態が0°、正の角度は反時計回り。変更後に「再生成」で反映する。
  原点の1区画がY軸対称になる角度は正方形が45°刻み、三角形が30°+60°刻み（−30°も可）。
  それ以外の角度は初期形状だけを表示し、対称性を満たさない旨を表示して増設を行わない。
- Inspectorの `Growth Batch Size` は連続増設の上限（1～6、追加時の初期値4）。1で旧方式になる。
- 生成後に「前」「次」「最終」とスライダーで、増設・補完の途中経過を確認する。
- 青は正方形、橙は三角形、明色はそのステップで追加した区画。凹みのある途中状態では白線で凸包を表示する。
- 到達／試行上限で停止、確定区画数、試行回数、補完失敗数、重なりによる取消数を表示する。
- カメラと区画の描画物は再生時に生成する。シーンを開いただけでは完成図形は表示しない。

## 生成ルールと今回の仮定

辺長1、Y軸対称。空き辺のある区画を等確率で抽選し、そこから空き辺を等確率で選ぶ。
正方形／正三角形を各50%で抽選して鏡映の組で追加する。
重なりを拒否し、増設後の凸包の内側を埋めて凸形状になれば確定する。
補完は追加面積の大きい候補を優先する貪欲法。補完できなければ、補完前の仮区画群から再び区画・辺・形状を抽選して増設する。
前回の凸包の外にも成長でき、増設後の新しい凸包で補完を再試行する。初期値では最大4組まで継続する。
途中で凸形状にできた時点で確定する。上限まで補完できない場合、または増設が重なった場合は、その回の仮増設全体を取り消す。
補完を含む区画数上限は「目安+32」（最大160）。試行上限までに目安を満たせなくても終了する。
再生中は一連の増設試行ごとに次フレームへ進める。連続増設と補完の探索は同期実行なので、大きな区画数では待ち時間が出る場合がある。

Python試作と同じシード番号でも、乱数生成器と幾何処理が異なるため、同じ形にはならない。
コンポーネントの初期値はシード2・目安24・試行上限160・正方形開始・連続増設4組。
C#側の独立実行では、この設定で22試行・24区画となった。ユーザーが保存したシーンのシード・区画数・初期形状は上書きしていない。

固定パターンの生成モードは追加していない。通常シードでの再現例・出現頻度の改善は未達であり、到達経路の確認と区別する。
