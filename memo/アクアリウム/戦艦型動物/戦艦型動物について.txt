■ 現行指定：区画・機能・代謝（2026-10-29）

本節はユーザー指定。後続の旧構想・仕様整理と食い違う箇所は本節を優先する。
区画機能・代謝は設計段階。形状生成はタイリングテストシーンで完成扱い。

◇定義・配置ロジック
・正方形と三角形の辺長は1で統一する。
・底辺が左を向いている状態を角度0degとする。
・現行テストシーンは初期図形を選択し、原点に重心を置く。角度はInspectorのenumで指定する。
  当初の正方形／三角形・−30/0/30/60degの抽選案から、テスト用の明示指定へ変更した。
・全体をY軸に関して線対称に配置する。
・プロシージャルに区画をタイリングする。最新指定により凸包の制約を廃止し、凹形状も許可する。
・生成した区画を配列に保存し、その中から基準区画を抽選して、空き辺に区画を増設する。
  抽選単位は区画とする。全区画の空き辺をまとめて抽選する方式にはしない。
・テストシーンの抽選・終了条件は下記の現行手順に従う。ゲーム本体の調整値は未決定。
・現行生成は重心原点・反時計回り正。正方形は左辺が底辺となる状態を0degとする。

◇三角形の頂点座標（計算補足）
※艦首・艦尾の形成案は後述の「艦首・艦尾の形成」を参照。
既存の形状構想と同じ正三角形とし、「底辺が左」は左側に垂直な底辺、
反対の頂点が右を向く状態と解釈する。辺長1、重心(0,0)、角度0degなら：
  A = (−√3/6, −1/2)
  B = ( √3/3,    0)
  C = (−√3/6,  1/2)
概数はA=(−0.288675,−0.5)、B=(0.577350,0)、C=(−0.288675,0.5)。
各辺長は1で、3頂点の平均は(0,0)。
反時計回りにθ回転する場合：x'=x cosθ−y sinθ、y'=x sinθ+y cosθ。
Y軸に関する鏡映は各頂点に(x,y)→(−x,y)を適用する。
この角度規約で三角形の鏡映後の向きは180deg−θ（形状としては120deg周期）。
試作design.jsonの既存の角度表記を、この新しい底辺基準へ変換済みとは扱わない。

◇艦首・艦尾の形成（完成扱いの現行方式）
現行方式では通常成長後、上下の実際の最遠端を5種類の完成形で判定する。
・軸上に重心がある三角形の頂点／正方形の頂点／正方形の水平辺。
・軸上の辺を共有する三角形2枚のひし形の頂点／正方形2枚の水平辺。
同じ高さに別の張り出しがあれば未完成。空き辺への三角形・正方形の対称追加を分岐探索する。
片端6手・候補1200件・保持128状態を現行の既定値とし、解のある側だけ確定する。
探索範囲は端から内側2以内・元の最大絶対X+1以内。未発見は元の形を維持し、完成保証はしない。
既に完成している反対側は崩さない。詳細と検証結果は「タイリングテストシーン.md」を参照。
◇共有辺への接続座標（計算補足）
上記の底辺基準・反時計回り正の角度規約で計算する。
・正三角形の辺から重心までの距離：T = √3/6。
・正方形の辺から重心までの距離：R = 0.5。
・基準図形の角度をθとすると、各辺の外向き法線方向φは以下となる。
  三角形：θ+60deg、θ+180deg、θ+300deg（θ±60degとθ+180deg）。
  正方形：θ、θ+90deg、θ+180deg、θ+270deg。
  正方形のθ±45degは頂点方向なので、辺への接続方向には使用しない。
・基準区画の重心をC、辺→重心距離をd_base、追加区画の同距離をd_nextとすると：
  C_next = C + (d_base + d_next) × (cosφ, sinφ)。
  d_base、d_nextには形状に応じてTまたはRを用いる。三角形同士は2T、
  三角形と正方形はT+R、正方形同士は2Rだけ重心を離す。
・追加図形の底辺を共有辺にする場合、追加図形の角度はφとする。
  追加図形の底辺の外向き法線はφ+180degとなり、基準図形側を向く。
・三角関数へ渡す際は角度をラジアンに変換する。

◇現行の生成手順（凸包廃止後）
1. 空き辺のある区画を等確率で抽選し、その区画の空き辺を等確率で選ぶ。
2. 正方形／正三角形を各50%で抽選し、共有辺に接続する。Y軸鏡映の組として配置する。
3. 既存区画または追加候補同士と内部が重なる場合は、その候補だけを却下する。
4. 重ならなければ即座に追加を確定し、区画配列と表示履歴へ記録する。
5. 増設確定後にY軸上の局所補完を行い、目安区画数または試行上限まで通常成長を繰り返す。
6. 端部形成が有効なら上端・下端を順に探索し、解のある側だけ追加する。
   対称ペア・局所補完・端部形成によって最終区画数が目安を超える場合がある。
・凸包計算、凸形状への限定、凹みの自動補完、補完失敗による巻き戻し、連続増設上限は廃止。
・三角形に正方形を接続できれば、その先の完成形を理由に取り消さない。
・通常成長では分岐探索は不要。端部形成のみ、候補区画と追加履歴を保持して分岐探索する。
・Y軸上の局所補完を追加。境界のX≈0.5→X≈0の辺と、その鏡映辺が作る辺長1の三角形の隙間だけを埋める。
  共有辺を除外し、第三頂点の一致・Y軸対称・既存区画と重ならないことを確認する。
  増設確定後に該当箇所がなくなるまで補完する。履歴は通常増設と区別して記録する。
  この補完により目安区画数を超える場合がある。その他の凹みや内部の空隙の補完は保証しない。
  現在の実装・検証は「タイリングテストシーン.md」を参照。

◇対称配置の現行動作
・重心原点の1区画がY軸対称になる角度は、正方形が45deg刻み、三角形が30deg+60deg刻み。
・それ以外の角度では初期形状のみ表示し、増設しない。位置をずらす方式は採用していない。
・区画の形状・配置はY軸対称とするが、区画機能はミラー配置にしない。
  各区画の役割は1区画ずつ独立して決める。

◇部位配置
区画は次のうち、いずれか一つの機能を持つ。
・砲塔：攻撃能力を持つ区画。回復フィールドなどもこの分類に含める。
・装甲：敵弾に対し、防御力を持つ区画。
・コア：破壊されると個体が即座に死亡する区画。
・原点に配置した基点区画を必ずコアとする。コアはこの1区画だけとする。
・残りの区画には、装甲と砲塔をおおよそ同数になるように割り当てる。
  残り区画数が偶数なら同数、奇数なら「装甲数＝砲塔数＋1」とする。
・必要数の装甲・砲塔の役割を用意してシャッフルし、非コア区画へ1区画ずつ割り当てる。
  形状のY軸鏡映関係とは無関係に割り当て、役割のミラー配置は行わない。
・装甲区画は、甲虫型と同様に区画内部へ円を描画して識別する。円の線色は赤とする。
全区画が砲塔を持つ旧構想は適用しない。区画数と砲塔数は別に扱う。
・砲塔は独立したGameObject・HP・描画を持たず、砲塔区画と同一のものとして扱う。
・砲塔区画が持つ具体的な能力は再定義予定。後段のA～E砲台案を現行仕様として使用しない。

◇代謝
・資源とSPはコア区画に集約する。他の区画ではNAとして扱い、管理しない。
・ただし、資源回収の当たり判定には他の区画も参照する。
・コア・装甲・砲塔の全区画は、個別の現在HPと最大HPを持つ。最大HPは役割によらず100で統一する。
・コアは自身の区画HPとは別に、全区画のHPを合計したコアHPを持つ。
  初期コア最大HPは全区画の最大HPの総和、初期コア現在HPは全区画の現在HPの総和とする。
・区画が脱落してもコア最大HPは初期値を維持し、減少させない。
・各区画がコアの炭素上限・SP上限へ加える値と、それぞれの初期値への寄与は100で統一する。
  初期状態のコア炭素・SPと各上限は、いずれも「全区画数×100」とする。
・各区画は、破壊時の炭素ドロップ判定に使う固定の炭素寄与量100を持つ。
  資源の現在値とSPの現在値をコアへ集約する方針は維持し、炭素寄与量を区画ごとの可変資源とは扱わない。
・旧表の本体HP200/500/1500と独立砲台HP100は使用しない。
・区画脱落後にコアの炭素・SP上限を変更するかは未決定。コア最大HPを維持する指定とは分けて扱う。

◇被弾・部位破壊
・弾が同時に複数区画へ命中した場合、該当区画のうちIDが最も小さい1区画だけを命中先とする。
  複数区画への同時命中処理には追加のリソースを割かない。
・装甲区画の装甲値は25とする。コア区画と砲塔区画の装甲値は0とする。
・非コア区画への有効ダメージは「max(0, 弾威力－該当区画の装甲値)」とする。
  有効ダメージを命中区画の現在HPとコア現在HPの両方から減算する。
・コアへ命中した場合、受けたダメージをコア現在HPから直接減算する。
  さらに同じ量のダメージを、その時点で脱落していない全区画の区画HPへ均等に分散する。
  各区画への分散量は「受けたダメージ÷生存区画数」とし、分散量の合計は元のダメージ量とする。
・直接ダメージと分散ダメージのどちらでも、減算後に各区画の破壊判定を行う。
・区画HPが0以下になった区画は脱落する。脱落時は、その区画の固定炭素寄与量を使って炭素ドロップ判定を行う。
・区画の脱落が確定した時点で、その区画の描画とColliderを即時無効化する。GameObject自体は削除せず非表示で残す。
・脱落後、コア区画との辺接続を失った区画は連鎖的に脱落する。
  連鎖脱落する各区画について、脱落直前の残存現在HPと同量をコア現在HPから減算する。
  連鎖脱落した区画も描画とColliderを即時無効化し、固定炭素寄与量100で炭素ドロップ判定を行う。
・同一フレームに複数区画の破壊・連鎖脱落が発生した場合は、GameObject配列のID昇順で処理する。
  先に処理した脱落による接続状態とコアHPの変化を、後続区画の判定へ反映する。
・コア区画の区画HPが0以下、またはコア現在HPが0以下になった場合、個体は即座に死亡する。
・個体死亡時に残っている未破壊区画も、各区画の固定炭素寄与量100をそのまま使って炭素ドロップ判定を行う。
・以前の「非コア区画破壊時にコアHP・資源・SPを1/N減らす」方式は適用しない。
  今回確定した、被弾時に区画HPとコアHPへ直接ダメージを与える方式で置き換える。
・物理的な残骸は現行仕様に含めない。非表示化したGameObjectを履歴・修復用に保持する。

◇回復手段
・通常HP回復と、脱落区画を戻す修復は別処理とする。
・通常HP回復は、コアに集約した現在資源量に比例させ、区画ごとに行う。回復係数と更新周期は未決定。
・脱落区画の修復は、修復機能を持つ砲塔区画が配置され、かつその区画が機能している場合だけ可能とする。
  修復費用、所要時間、修復順序、復帰HP、接続条件は砲塔能力の再定義時に決める。

■ 本体・部位・砲台の過去資料整理（2026-10-28）

位置づけ：既存資料の履歴。2026-10-29に確定した上段の現行指定と矛盾する数値・砲台構造・未決定記述は適用しない。
旧A～E砲台案は再定義前の参考であり、現行の砲塔能力ではない。
戦艦型動物という総称にはフリゲート艦型・駆逐艦型・戦艦型を含む。
以下の「戦艦型」は、そのうち第三層の艦種を指す。

【1. 本体】

一個体としての移動・追跡と、生存に関わる単位。下表の本体HPは旧記録であり、現行では区画HP100と初期全区画HP総和のコアHPを使用する。

戦艦型               第三層    1500  8～14(~E)    白色12角形

  戦艦型動物以外。逃走対象は自身以上の戦艦型動物。同格は攻撃・逃走の両対象になる。
・旧表の「肉食動物のみ」で対象を再制限しない。攻撃対象は通常弾の命中対象も制限する。
・複数砲台の射程が異なる場合の維持距離、攻撃と逃走の優先順位は未決定。

◇艦首・艦尾の原案と反例
以下はユーザーの原案。30度除外やX座標の分解規則は、そのまま実装したものではない。

概要：Y座標の最小側・最大側で、三角形の頂点、正方形の頂点または辺を上下へ向けたい。
追加指定：線対称に接合したひし形の頂点が下を向く形も認める。
全体の凸包は使わず、辺に区画を追加して軸上の端部を形成する構想。

ユーザー提示の反例：シード2714、区画数32、試行数233、三角形30°スタート。
28区画の頂点：(0.86,-3.81)、(1.73,-4.31)、(1.36,-2.94)。
8区画の頂点(0,1.15)を一方の端部にする。
訂正後の追加順序（座標は提示された概数）：
1. (0.86,-3.81)―(1.73,-4.31)の辺へ、第三頂点(0.86,-4.81)の三角形を追加。
2. (0.86,-3.81)―(0.86,-4.81)の辺へ、第三頂点(0,-4.31)の三角形を追加。
3. (0.86,-4.81)―(0,-4.31)の辺へ、第三頂点(0,-5.31)の三角形を追加。
鏡映側にも同様に追加し、下側の端部を(0,-5.31)とする。以前の(0,-4.81)指定はこの訂正で置き換える。
最後の左右の三角形はY軸上の辺を共有し、下向きの頂点を持つひし形になる。
計算では0.86を√3/2、1.73を√3として辺長1を保つ。丸めた表示座標をそのまま生成座標には使用しない。
この復元で追加6三角形の全辺長1・相互の内部重なりなしを数値確認。
既存の船体全体との重なりは未確認。

ユーザー提示の処理案：
・Y座標が最小／最大の頂点を探す。
・自身―隣の頂点―その隣の頂点の角度差が30°の条件に該当する場合は除外し、次のY座標で検索する。
・X=0で同Y座標の別頂点がない場合は終了。同Y座標の頂点がある場合の「X=1以外なら終了」の条件は要整理。
・該当頂点に属する辺を取り、atan2によって辺の角度を取得する。
・X座標を0.5、1で分解する案。
・(1,n)―(1,n+1)の場合：(1,n),(1,n+1),(0,n),(0,n+1)の正方形を追加して終了。
・(0.5,n)―(0.5,n+1)の場合：(0.5,n),(0.5,n+1),(-0.5,n),(-0.5,n+1)の正方形を追加して終了。
  前者は鏡映側にも正方形、後者は自身が対称なので1区画となる。

原案で未整理だった点（現行方式の残作業ではない）：
・30°は外周の方向変化なのか、内角なのか。隣接頂点は区画内の順序か、共有辺を除いた外周順序か。
・0.5と1の整数個の和だけでは√3/2のX座標を表せない。
  正方形・正三角形の回転配置を扱うには、今回の例では√3/2を含む成分で考える必要がある。
  「素因数分解」は未確定の探索案として扱い、勝手に別方式へ確定しない。
・最小／最大の検索を開始する位置、同Y頂点の扱い、上側・下側の終了条件、増設が重なる場合の代替探索。
・ゲーム本体での実行時点・追加数・試行上限は未決定。試作の設定は本節冒頭を参照。

◇旧生成手順の案（凸包廃止により現行には適用しない）
2026-10-28追記：テストシーンでは、補完できないときに最大4組までランダム増設を継続する方式を追加した。
途中の凹みを許し、新しい凸包の内側で補完を再試行する。区画単位の抽選は維持する。
参照11角形への到達経路は指定抽選列で検証済みだが、通常シードでの完全一致例は未確認。
現在の実装・検証範囲は「タイリングテストシーン.md」を参照。以下は当初の手順案として残す。
区画単位の抽選だけでは、全体が凸多角形になる保証はない。
以下は区画抽選・Y軸対称・完成時の凸形状を満たすための手順案で、実装・成立検証は未実施。
1. 全区画を配列で管理し、増設候補の区画を抽選する。
   区画ごとに形状・重心・角度・機能・辺ごとの接続先を保持する案とする。
   増設不能な区画を抽選対象から除外する補助リストを持つ案もあるが、抽選単位は区画のまま。
2. 抽選した区画の空き辺と追加形状を選び、接続座標を計算する。
3. 追加区画とY軸鏡映区画を組にして検査する。既存区画との内部の重なりに加え、
   追加候補同士の内部の重なりも検査する。辺・頂点の接触は内部の重なりと区別する。
   鏡映後に完全に同じ区画となる場合は1区画だけ追加する。
4. 重なりがなければ仮追加し、外周に凹みが生じた場合は、対称性を保って追加区画で埋める。
5. 穴のない単一の凸多角形になれば、その増設を確定する。
   埋められない場合や試行上限に達した場合は、その増設と補完区画をまとめて取り消す。

・毎回1区画を追加した直後に凸であることを要求すると、途中の凹みが必要な成長を妨げる。
  そのため「抽選による増設＋凹みの補完」を一まとまりとして凸を判定する案。
・凹みが常に埋まるとは限らない。補完の探索方法・試行上限・行き詰まり時の終了／再生成は未決定。
・一方の形状が置けなくても他方が置ける場合があるため、1回の失敗だけでその辺を増設不能としない案。
・凸の判定では外周の一直線上の継ぎ目を角として数えず、内部の穴も別途確認する。
・対称配置や凹みの補完では複数区画を追加するため、任意の指定区画数ぴったりで止められる保証はない。
  区画数を目安／範囲とするか、指定数を満たすまで再生成するかは未決定。
