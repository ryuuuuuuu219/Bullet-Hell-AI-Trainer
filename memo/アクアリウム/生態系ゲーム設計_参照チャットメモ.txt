■ 6. 基本仕様
・対象種の連続存続時間が規定値に到達した瞬間に、マイルストーン達成を確定する。
・カードとステージを即時開放する。
・達成後もシミュレーションは継続する。
・獲得したカードは次回の試行から使用可能となり、現在のシミュレーションには適用しない。
・達成履歴と報酬は永続保存する。報酬の重複取得はない。
・カード装備構成は全ステージ共通。
・現在のシミュレーション状態は、現段階では保存対象外。

■ 7. マイルストーン達成時の一連の処理
1. シミュレーションを更新する。
2. 対象種の個体数と連続存続時間を更新する。
3. 未達成マイルストーンについて、存続時間が要求値以上か判定する。
4. 初回達成分の達成履歴・カード開放・ステージ開放を、同じメモリ上の進捗データへ一括反映する。
5. 報酬を含む進捗を保存する。
6. 達成を通知し、観察を継続する。
同じ時刻に複数達成した場合、全報酬をまとめて処理し、保存は1回にまとめる。

■ 8. 存続時間の計測
対象種を s、個体数を N_s(t)、ステージ開始時刻を t_start とする。
ステージ開始時から対象種が連続して存在する間：
    T_s(t) = t - t_start
個体数が0になった時点で計測を終了する。
絶滅を検出した更新では、存続時間を増加させない。
一度絶滅した後に再スポーンしても、同じ試行の存続時間は再開しない。

境界の例：59.9秒で生存し、次の更新で絶滅した場合、60秒達成とするかは実際の絶滅時刻に依存する。
正確な死亡時刻を取得できない場合は、シミュレーションの固定更新時刻を基準にする方式が提案されている。

計測状態の例（C#）：
public enum SpeciesSurvivalState
{
    NotStarted,
    Surviving,
    Extinct
}

推奨案：初期スポーンで対象種の存在を確認し、存在しなければステージを開始できないようにする。

■ 9. マイルストーン管理クラス（実装例）
StageData に定義されたマイルストーンを専用クラスで監視する。
達成判定と進捗更新を担い、報酬付与とファイル保存は別クラスへ分離する。
以下は提供本文の主要部分の例であり、プロジェクトに実装したコードではない。

public class MilestoneManager
{
    private readonly StageData stage;
    private readonly PlayerProgress progress;
    private readonly StageProgress stageProgress;

    private readonly HashSet<string> achievedIds;

    public MilestoneManager(
        StageData stage,
        PlayerProgress progress,
        StageProgress stageProgress)
    {
        this.stage = stage;
        this.progress = progress;
        this.stageProgress = stageProgress;

        achievedIds = new HashSet<string>(
            stageProgress.achievedMilestoneIds);
    }

    public List<MilestoneData> Evaluate(float survivalTime)
    {
        var newlyAchieved = new List<MilestoneData>();

        foreach (var milestone in stage.milestones)
        {
            if (achievedIds.Contains(milestone.milestoneId))
                continue;

            if (survivalTime < milestone.requiredSurvivalTime)
                continue;

            achievedIds.Add(milestone.milestoneId);

            stageProgress.achievedMilestoneIds.Add(
                milestone.milestoneId);

            newlyAchieved.Add(milestone);
        }

        stageProgress.bestSurvivalTime = Mathf.Max(
            stageProgress.bestSurvivalTime,
            survivalTime);

        return newlyAchieved;
    }
}

■ 10. 報酬の一括付与（実装例）
public void GrantRewards(
    List<MilestoneData> milestones,
    PlayerProgress progress)
{
    var unlockedCards = new HashSet<string>(
        progress.unlockedCardIds);

    var unlockedStages = new HashSet<string>(
        progress.unlockedStageIds);

    foreach (var milestone in milestones)
    {
        foreach (var card in milestone.rewardCards)
            unlockedCards.Add(card.cardId);

        foreach (var stage in milestone.unlockStages)
            unlockedStages.Add(stage.stageId);
    }

    progress.unlockedCardIds = unlockedCards.ToList();
    progress.unlockedStageIds = unlockedStages.ToList();
}

HashSet により、同じカード・ステージが複数の報酬に含まれていても重複追加しない。
達成履歴だけを先に保存すると報酬と不整合になり得るため、両方を同じ進捗データに反映してから一括保存する。

■ 11. 保存処理の安全性（推奨方式）
progress.json：現在の有効なセーブデータ。
progress.tmp ：新しいデータを一時的に書き込むファイル。
progress.bak ：前回の正常なセーブデータ。

保存手順：
1. 一時ファイルへ書き込む。
2. 書き込み成功を確認する。
3. 本ファイルを置換する。
4. バックアップを更新する。

本ファイルが破損している場合は、バックアップを読み込めるようにする。
通常の File.WriteAllText だけでは、保存中のアプリ終了による破損の可能性がある。
置換が原子的に行えるかはOS・ファイルシステムに依存するため、Unityの対応プラットフォームごとに検証が必要。
上記は提供本文の概略手順であり、置換・バックアップ更新の具体的なAPIは示されていない。

■ 12. 達成通知UI（提案）
観察を妨げないよう画面端に小さな通知を表示し、シミュレーションは停止しない。
表示例（カード名・時間は仮設定）：

    草食動物A：180秒存続
    新カード「繁殖促進」を開放
    Stage 02 を開放

複数同時達成時は、キューで順番に表示するか、一つにまとめる。
どちらを採用するかは提供本文では選択されていない。

■ 13. 永続保存と実行状態の区別
データ                         永続保存
達成済みマイルストーン           する
開放済みカード                   する
開放済みステージ                 する
全ステージ共通ロードアウト       する
ステージ最高存続時間             する
現在の動物位置                   しない
現在の個体資源量                 しない
現在の生態系状態                 しない

再起動時はシミュレーションを新規開始するが、達成履歴と獲得カードは維持する。
