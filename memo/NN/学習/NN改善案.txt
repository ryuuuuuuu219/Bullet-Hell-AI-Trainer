# NN教師学習・遺伝保存 改善仕様

## 目的

現在のオンライン1件学習を、全学習個体で共有する32件の教師サンプルと平均勾配によるミニバッチ学習へ変更する。

手動操作の教師情報を手動操作個体のNNだけへ保存するのではなく、遺伝的アルゴリズムの対象となる各個体NNへ反映する。

## 現在のNN構造

| 項目 | 内容 |
| --- | --- |
| NN | 入力85、隠れ層16・12、出力2の全結合MLP |
| 活性化関数 | 全層 `tanh` |
| 出力 | X・Y移動量 |
| 教師 | 手動操作、補助用回避ベクトル指示器 |
| 教師損失 | NN出力と教師XYの二乗誤差 |
| 世代更新 | エリート保存、トーナメント選択、一様交叉、ガウス突然変異、ランダム個体投入 |
| 課題 | A～D・Ranking。Rankingでは学習と世代更新を行わない |

## 現在の世代更新とPlayerPrefs保存

通常の世代更新では、世代終了時に各個体のNNを `AiSaveData` として取得する。オンライン逆伝播で変更された重みも、この時点の `AiSaveData` に含まれる。

次世代は、その世代の全候補から次のように生成される。

1. 総合評価値上位のエリート1～2個体を無変更で複製する。
2. 完全ランダムなNNを2個体生成する。
3. 残りをトーナメント選択、一様交叉、ガウス突然変異で生成する。
4. 生成した `AiSaveData` を新しい各個体へ適用する。

同じステージ内の世代更新では、全候補から生成した次世代データをメモリ上で直接配布する。PlayerPrefsに全個体群は保存しない。

PlayerPrefsには代表NNを1個だけ保存する。ゲームやステージを再開するときは、この代表NNを起点として個体群を再構築する。RankingではPlayerPrefsに保存された代表NNを1個だけ読み込み、重みを更新せずに使用する。

## 改善後の共有教師サンプル

全学習個体で共有する固定長配列を使用する。

```csharp
private const int SharedTeacherSampleCapacity = 32;

private static readonly TeacherSample[] sharedTeacherSamples =
    new TeacherSample[SharedTeacherSampleCapacity];

private static int sharedTeacherSampleCount;
```

`frozenTeacherGenome` は導入しない。PlayerPrefsに保存されたNNを、共有教師サンプル生成用の固定教師NNとしては使用しない。

### TeacherSampleに保存する内容

共有するのは重み、重み誤差、勾配ではない。次の教師データだけを共有する。

```csharp
public sealed class TeacherSample
{
    public float[] inputs;
    public Vector2 targetMovement;
    public TeacherTargetSource source;
}
```

| フィールド | 内容 |
| --- | --- |
| `inputs` | サンプル取得時点の85個のセンサー入力の複製 |
| `targetMovement` | プレイヤー入力または補助用回避ベクトル指示器が示した正解XY |
| `source` | 手動操作由来か、補助用回避ベクトル指示器由来かを示す値 |

個体ごとにNNの重みと中間層出力が異なるため、1個体で算出した重み勾配を他個体へ共有しない。各個体は共有された同一の入力と正解XYから、自分自身の現在のNNに対する勾配を計算する。

## 教師サンプルの登録

### 手動操作

手動操作中は0.5秒ごとに判定し、50%の確率で教師サンプルを1件登録する。

登録内容は次のとおり。

- 入力：その時点の85個のセンサー入力
- 正解：その時点のプレイヤー移動入力XY
- 種別：`TeacherTargetSource.ManualPointer`

平均登録速度は1秒あたり1件となる。

### 各AI個体

各AI個体は0.5秒ごとに判定し、10%の確率で教師サンプルを1件登録する。

登録内容は次のとおり。

- 入力：その個体の、その時点の85個のセンサー入力
- 正解：その時点で補助用回避ベクトル指示器が示した移動XY
- 種別：`TeacherTargetSource.ScriptedProvider`

1個体あたりの平均登録速度は1秒あたり0.2件となる。個体数5の場合、AI全体では平均1秒あたり1件となる。

補助用回避ベクトル指示器が無効な場合、AI個体から教師サンプルを登録しない。Rankingでは教師サンプルの登録と重み更新を行わない。

## 配列への登録方法

共有配列が32件で埋まるまでは、空いているIDへ順番に登録する。

共有配列が32件で埋まった後は、`0～31` からランダムに選んだIDを新しい教師サンプルで上書きする。

最初からランダムIDを使用すると、未使用IDが残っている状態で同じIDを繰り返し上書きする可能性があるため、満杯になるまではランダム置換を行わない。

## 共有教師サンプルの保持

共有教師サンプルは、世代変更、ステージ変更、課題カテゴリ変更をまたいで維持する。

世代設定を変更した場合も、変更前後でNNの入力ノード数が同じなら共有教師サンプルを維持する。センサー入力の有効・無効や扇形センサー設定を変更しても、入力ノード数が変わらない限り維持する。

世代設定変更によってNNの入力ノード数が変わった場合は、新しい入力ノード数と `TeacherSample.inputs.Length` が一致しない教師サンプルを破棄する。すべての既存サンプルが変更前の入力ノード数である場合、共有配列をクリアして新しい入力構成のサンプルを蓄積し直す。

共有配列は `static` であり、アプリケーション終了後までは永続保存しない。

## 各個体NNのミニバッチ学習

各学習個体は0.5秒ごとに、その時点で共有配列に登録されている全教師サンプルを使用する。

1. 全サンプルを同じ更新前の重みで順伝播する。
2. 各サンプルについて、NN出力と教師XYから損失と勾配を計算する。
3. 各パラメータについて全サンプルの勾配を合計する。
4. 合計勾配を有効サンプル数で割り、平均勾配を求める。
5. 平均勾配で各パラメータを1回だけ更新する。

有効サンプル数を `N` としたとき、平均勾配は次のとおり。

```text
averageGradient = (gradient[0] + ... + gradient[N - 1]) / N
```

共有配列が空の場合は学習しない。1～31件の場合は存在する件数で平均し、32件の場合は32件すべてで平均する。

サンプルごとに重みを更新しながら32回連続で学習する方式にはしない。32件分の勾配計算が完了するまで重みを変更せず、最後に1回だけ更新する。

32件すべての平均勾配を使用するため、学習時にサンプル順をシャッフルする必要はない。ランダム性は満杯後の配列ID置換に使用する。

勾配蓄積用の配列は各 `Aidata` が個別に持ち、`static` にしない。

## 手動操作NNの扱い

改善後は、手動操作個体のNNをPlayerPrefsへ直接保存しない。手動操作の学習情報は、共有 `TeacherSample[32]` を介して遺伝的アルゴリズム対象の各個体NNへ反映する。

手動操作個体は、従来どおり遺伝的アルゴリズムの評価候補から除外する。

各遺伝個体は手動操作由来と補助用回避ベクトル指示器由来の共有サンプルで逆伝播される。その結果を含む各個体NNを世代終了時に評価し、次世代へ遺伝させる。

## PlayerPrefsへ保存するNN

PlayerPrefsには、遺伝的アルゴリズム対象個体のうち、ユーザーが設定画面で選択した保存評価軸における最良個体を1個保存する。

保存評価軸は次のいずれか。

- 与ダメージ
- 生存時間
- 画面端衝突累計時間
- 画面中央からの距離総和

同値の場合は総合評価値が高い個体を優先する。

手動操作個体のNNによるPlayerPrefs上書きは廃止する。手動操作の影響は共有教師サンプルを通じて各遺伝個体へ反映され、その結果として評価軸で選ばれた最良個体に含まれる。

## 改善後の全体フロー

```text
手動操作
  └─ 0.5秒ごと・50%で入力85＋プレイヤー入力XYを共有配列へ登録

各AI個体
  └─ 0.5秒ごと・10%で入力85＋回避ベクトルXYを共有配列へ登録

static TeacherSample[32]
  └─ 未満時は空きIDへ登録、満杯後はランダムIDを置換

各学習個体
  └─ 0.5秒ごとに全有効サンプルの平均勾配で自分のNNを1回更新

世代終了
  ├─ 全遺伝個体を総合評価値で選択・交叉・突然変異して次世代化
  └─ ユーザー指定保存評価軸の最良個体をPlayerPrefsへ保存

手動操作個体
  └─ 遺伝候補外、PlayerPrefsへ直接保存しない
```

## 実装時の決定

- 手動操作由来と補助用回避ベクトル指示器由来を固定枠へ分けず、同一配列のランダム置換で管理する。
- 0.5秒周期はゲーム内時間に追従する `Time.time` で計測する。ポーズ中は登録と学習を進めない。
