# 現状構造で再現不可能な弾幕

最終確認日：2026-09-08

## この文書の目的

この文書は、現在の弾幕定義へ数値や配列を追加するだけでは再現できず、実装構造の拡張が必要な弾幕を残すための記録である。

ここでいう「再現不可能」は、専用コードを新しく書けば実現できるという意味ではなく、次の既存経路だけでは意図した挙動を表現できないという意味で使う。

- `BulletHellStageAttackDefinitions` にステージを追加する
- `BulletHellShotDefinition` と `BulletStructure` の既存引数を組み合わせる
- `BulletHellShooter`、`bullet`、`LaserAttack` の現行処理をそのまま使う

見た目だけが近い代用品は「再現可能」と数えない。軌道、発生条件、時間関係、当たり判定が設計意図どおり一致することを再現条件とする。

## 現在表現できる範囲

現状の弾幕は、おおむね次の組み合わせで構成される。

- 固定されたボス位置を起点とする、周期発射と連射
- 自機狙い、固定下方向、およびそれらを基準にした角度配列
- 直進、一定曲率、純粋追尾、比例航法
- 一定時間だけの線形加減速と角加速度
- 時間を条件とする単発または周期分裂
- 親弾の進行方向基準または分裂時の自機狙いによる子弾生成
- 直線の予告線と、位置・方向が生成時に固定される直線レーザー
- 弾速と発射周期に対する、周期単位で共通の±15%ゆらぎ

多段分裂や、飛翔中の弾を発射源として子弾・レーザーを繰り返し生成する構成は、すでに表現可能である。

## 再現不可能な弾幕

### 1. 発射源そのものが移動する弾幕

例：画面端を周回する砲台、複数の固定砲台、ボスの左右移動に追従する扇状弾、親機から分離して独立移動する発射装置。

再現できない理由：ステージ開始時に生成される発射源は単一のボスで、発射位置は発射時の `source.position` に固定される。発射源の移動経路、複数発射源、発射源の生成・破棄を弾幕定義に持たない。

必要な拡張：発射源定義、発射源ごとの移動定義、複数発射源を同期するタイムライン。

### 2. 任意の軌道をたどる弾

例：正弦波、ジグザグ、ウェイポイント移動、一定位置を中心とする公転、停止後の再加速、逆走、画面端での反射。

再現できない理由：弾の運動は `Straight`、`ConstantTurn`、`Homing`、`ProportionalNavigation` の4種類に限られる。速度と角速度の変化も一定時間の線形変化だけで、位置や経過段階に応じた運動モードの切り替えを表現できない。

必要な拡張：時間区間ごとの運動フェーズ、カーブまたは関数による速度・角速度、ウェイポイント・軌道中心・反射規則。

### 3. 時間以外を条件に変化する弾

例：指定座標への到達で分裂、自機との距離で起爆、画面内への進入で加速、壁への接触で反射、被弾時に子弾を放つ弾。

再現できない理由：分裂開始条件は生成からの経過時間だけである。弾の位置、距離、衝突、速度、他の弾の状態を条件として参照する仕組みがない。

必要な拡張：イベント条件の共通定義と、到達・距離・衝突・被弾などのトリガー。

### 4. 発射後に向きや起点が動くレーザー

例：薙ぎ払いレーザー、自機を追尾するレーザー、ボスに追従するレーザー、伸びていくレーザー、両端が移動するレーザー。

再現できない理由：`LaserAttack.Configure` の時点で起点と方向が確定し、予告中も照射中も更新されない。長さと幅も時間変化せず、当たり判定は一本の静止直線である。

必要な拡張：起点・方向の追従先、角速度、長さと幅の時間変化、および毎フレーム更新される当たり判定。

### 5. 曲線・折れ線・面を使うレーザー

例：曲がるレーザー、折れ曲がるレーザー、円環レーザー、扇形照射、閉じてくるレーザー壁。

再現できない理由：レーザーの描画と判定は、起点から一方向へ伸びる一本の線分または半直線だけで構成される。

必要な拡張：複数線分または曲線の形状データ、その形状と一致する当たり判定、AIセンサーへ渡す脅威表現。

### 6. 弾同士または弾と環境が相互作用する弾幕

例：弾同士の衝突・合体・相殺、別の弾に引かれる弾、重力場で曲がる弾、壁や障害物で跳ねる弾。

再現できない理由：敵弾が扱う衝突結果は対応レイヤーの自機への命中だけであり、他の弾や環境を参照して運動や構造を変える処理がない。

必要な拡張：相互作用対象の分類、衝突・力場処理、同一論理レイヤー内だけで相互作用させる規則。

### 7. ゲーム状態に応じて分岐する弾幕

例：自機の位置で左右どちらかの弾幕へ分岐、残り生存時間でフェーズ移行、被弾回数で難度変更、破壊した部位に応じて発射系列を変更。

再現できない理由：現行スケジューラは初期遅延、周期、連射、周期ごとの間隔短縮を実行するだけで、条件分岐や共有状態を持つイベント列ではない。

必要な拡張：ステージ状態、条件式、フェーズ遷移、弾幕系列の開始・停止命令。

### 8. 複雑な確率弾幕

例：弾ごとに角度を乱す、候補パターンから重み付き抽選する、way数を毎回変える、一定範囲内の位置へランダム生成する。

再現できない理由：現在の乱数は弾速と発射周期の±15%だけで、同一周期内では共通値を使う。角度、弾数、発射位置、構造、分岐確率は抽選できない。

必要な拡張：項目別の乱数範囲、抽選単位、重み付き候補、再現用乱数シード。

### 9. 子弾が親弾の運動量や状態を引き継ぐ弾幕

例：親弾の速度へ子弾の相対速度を加える、親弾の残り旋回量を継承する、親弾の経過時間に応じて子弾性能を変える。

再現できない理由：子弾は指定方向と `childStructure.Speed` から新しい速度を作る。親弾の速度、加速度の進行度、旋回量などを子弾パラメータへ渡す仕組みがない。

必要な拡張：継承する状態の選択、親基準の相対速度、生成時パラメータ計算。

### 10. 30秒を超えて残り続ける弾による弾幕

例：永久設置弾、30秒を超えて成長する弾幕、非常に長い周期で同じ親弾から生成を続ける弾幕。

再現できない理由：敵弾は挙動や分裂回数に関係なく、生成から30秒でプールへ戻される。

必要な拡張：構造ごとの寿命、無限寿命の扱い、画面外回収と最大同時数の安全策。

## 近似はできるが同一にはならない例

| 欲しい弾幕 | 現状の近似 | 一致しない点 |
| --- | --- | --- |
| 円運動する弾 | 一定曲率弾 | 特定の中心を周回せず、初速と角速度から決まる円軌道になる |
| 薙ぎ払いレーザー | 短い固定レーザーを角度違いで連射 | 一本の連続したレーザーが回転する当たり判定にはならない |
| 座標到達で分裂 | 到達予想時間を分裂時刻として指定 | 加減速、誘導、フレーム差、自機位置の変化で分裂位置がずれる |
| ランダム散弾 | 周期単位の弾速ゆらぎ | 弾ごとの角度や速度は独立に乱れない |
| 移動砲台 | 飛翔中の親弾から周期分裂 | 親弾は固定の子弾生成規則しか持てず、任意の射撃系列を実行できない |


## 更新規則

- 数値調整だけで実現できると判明した項目は、この一覧から削除せず「対応済み」へ移し、使用した定義を記す。
- 専用実装で一例だけ動いた状態と、汎用構造として弾幕定義から再利用できる状態を分ける。
- 実装可否と、AIがその脅威を観測できるかを分けて確認する。
- レーザーや新しい形状を追加するときは、描画、当たり判定、警告表示、AI入力の4点を同時に確認する。
- 実装後はC#コンパイル確認とUnity上の目視・当たり判定確認を別々に記録する。
